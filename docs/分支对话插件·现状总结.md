## 1.1 图形化的口径与实现对照（**判定"做没做完"就看这条**）

| 要素 | 要求（可判定） | 现在的实现 | 状态 |
| --- | --- | --- | --- |
| 节点 | **有边框的矩形框**，框内放轮次号 / 标题 / 状态点 / 折叠把手 / 「＋」 | `.dsh-branch-node`：绝对定位、固定 `208×62`、`border: 1px`、框内含把手/状态点/「第 N 轮」/两行截断标题/「＋」 | ✅ |
| 关系 | 父子节点之间**画出来的连线**（SVG 层），端点贴框边缘；同一会话相邻轮次的**轴线也要可见** | `layoutTree` 为每条可见连接产出正交折线（`edges[].path`），页面在 `.dsh-branch-wires` 里逐条画；**主轴**（同会话相邻轮次）画**实线**（父下缘中点 → 子上缘中点，竖线走两框之间的空隙）、跨会话分支画**虚线**（父右缘中点 → 车道 → 子左缘中点）。**同会话轮次在树文档里是平铺的**，所以主轴在**显示层合成**（`synthetic: true`，不改树文档/导出） | ✅ |
| 布局 | **二维坐标** `{x, y}`：**主轴向下、分支向右** | 主轴（同会话相邻轮次）同列向下叠（每轮 + `NODE_H+ROW_GAP`）；分支（跨会话）向右每层 + `NODE_W+LEVEL_GAP`，同一父节点的多个分支同列上下叠；互不相连的根各自成块自上而下叠放 | ✅ |
| 折叠 | 折叠后后代与连线消失，**剩余节点重排** | 折叠节点的后代**不进 `nodes` 也不进 `edges`**；**主轴上的下游轮次也一起隐藏**（它是这一轮的延续——合成链上的隐藏数单独统计，否则会"越级上前"） | ✅ |
| 窄屏 | 画布**双向滚动 + 缩放**，仍是"框 + 线" | `.dsh-branch-canvas`（`overflow:auto` 双向滚动）+ `scale()` 缩放（30%~200%）；**自动适配**只在"用户没手动调过缩放"时生效（否则抢用户的选择），F-6 实测过这条边界；容器变窄只让滚动条出现，**框与线不退化** | ✅ |

| **右侧侧边栏（详情列）也能打开**（M7） | ✅ **已实现 + 真机验证（2026-10-17）** | 同一画布挂到官方右侧详情列：页面型页签 + `guide` 数组（引导页入口）+ keyed 内容座位。真机 F-9：`Ctrl+Shift+B` → 引导页「分支对话」→ 右侧栏渲染 9 框；F-10：点「在右侧打开」→ 切回对话并开页签，回来缩放仍在。**关键约束**：右侧详情列是按会话的，全局面板占中央列时 `openTab` 会抛，所以按钮先 `selectPanel(null)` 切回对话。左侧入口**一行未改** |
| **右栏里就地建子会话**（F-14） | ✅ **已实现 + 真机探针验证（2026-10-17）** | 右栏画布点「＋」弹出**紧凑表单**（`BranchCreateForm compact`：标题 + 轮次说明 + 两行提问 + 两个按钮，轮次固定为被点的框）；提交后右栏框数 +1、新连线起点=被点的框、树 id 不变。产物层由 `client-bundle.mjs` / `served-bundle.mjs` 的标记断言兜底 |

**参考观感**：Visio / draw.io 的流程图——框 + 连线 + 方向感。
**实现位置**：`src/client/tree-layout.ts`（二维布局 + 边，纯函数）· `panel.tsx`（节点框 + SVG 连线层 + 缩放）·
`panel.css`（画布/框/线样式）· `view-state.ts`（缩放/滚动跨面板切换存活）；
设计口径见 [设计文档 §3.2](分支对话插件·设计文档.md)、落地记录见其 §6.7.6。

> ⚠️ **已被推翻的旧取舍（留个记录）**：早先写"布局向右生长，同一会话连续 N 轮会排成 8000px 长链"。
> 真机数据表明同会话轮次是**平铺的兄弟**，主轴现已改为**纵向**（同列上下叠），12 轮画布只占**一列宽**（256px）；
> 只有**分支多**才会向右变宽。

### 4.1 真机轮次二（只有真机才会暴露）

一共 9 个，全部已修 + 有回归用例。按发现顺序：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |

### 4.3 P0-A 人工交互轮（2026-10-17）：缺陷 27 = 建子会话的通道错了

**管理者点出来的两个现象**：① 子会话建出来了但**挂不到父会话上**；② 打开子会话后它在画布上**被当成新根**。

**根因（实时 inspection 拿到的原文）**：`sessions` 服务明说
"**a session published outside that lifecycle persists nothing**"——我们的 `createChildSession` 走的正是
`ctx.sessions.create()`：铸出的是 `session-<n>` **计数器号**、不落盘、不进 `sessionController.list()`，
所以树上的节点永远匹配不到真实会话（真机存储里确实躺着 `sessionId: "session-1"` 的节点），
打开真实子会话时 `adopt` 只好给它建一棵新树。**外加一个独立缺陷**：挂载点取的是该会话的**第一个**
qa 节点，所以在第 2 轮上建的分支会挂到第 1 轮下面。

**修法**：改走 `ctx.agents.create({ sessionId: session-<uuid>, meta, agentOptions, setup })`（官方
`sessionController.create` 同款：`presets.resolve` + `setup: presets.mount`）；挂载点按 `parentTurn`
选（`anchorNodeFor`）；`syncTurns` 让占位节点认领第一个轮次；`adoptSession` 以 `inspect` 为准（刚建、
还没落盘也能读）。诊断字段 `sessions` → `agents`。

**真机证据（隔离 profile）**：子会话立刻落盘（头里 `parentSession`/`isSeeded:false`/`cwd`/`agentPreset`
全对）、`adopt` 与父会话同树、新节点挂在**第 2 轮**的 `children` 下；UI 探针点「＋」→ 填首句 → 提交：
框数 3→4、新连线起点就是被点的那个框、树 id 未变、无报错。回归用例见 `branch-m1-cases.mjs`（新增 3 条）。

### 4.4 缺陷 29（2026-10-17）：新建的子对话没进父会话的工作区

**现象**：在节点上「＋」建出来的子对话，侧边栏里落在「**未分组**」，而不是父对话那个工作区。

**根因**：官方工作区的成员资格是**账本制**——`subsystems/workspace.zh.md` 原话：所有权的真源是
工作区记录里的 `sessionIds`，**绝不从会话 cwd 派生**；成员资格要求「账本里有这个 id」**且**
「会话头 cwd 等于工作区路径」两条同时成立。我们建子会话时只把 `cwd` 传给了 Agent 工厂，
**没有人调 `attachSession`**，于是账本里没有它——它就是"未分组"。

**修法**（`session-model.ts` + `branch-service.ts`）：新增
`attachToParentWorkspace(model, childSessionId, parentSessionId)`——用 `ctx.workspaceRegistry.list()`
按**父会话**反查工作区（`sessionIds.includes(parentSessionId)`），再 `attachSession(子会话)`；
建分支时在"建出会话"之后立刻调用，**失败不拦路**（会话已经建好，最坏只是仍在未分组，用可读原因告知）。
回包新增 `workspaceAttached` / `workspaceId` / `workspaceError` 三个字段，面板状态行会明说挂没挂上；
`/branch/diagnostics` 新增 `workspaces` 能力位，自检区显示「工作区注册表」。

**验证**：

- 冒烟 `branch-m1-cases` **17 → 20**：子会话确实进了父会话的工作区（账本里有它、`workspaceAttached=true`）；
  父会话自己就没工作区时**照常建成**、回包说清"没挂上"；部署没有 `workspaceRegistry` 时同样降级不抛错。
- **真机实测（web profile，共用同一个 `$DSH_HOME`）**：`POST /branch/create` 返回
  `workspaceAttached:true, workspaceId:4b063222-…`（=「f分支对话插件」那个工作区），
  并且 `storages/workspace.json` 里该工作区的 `sessionIds` **前插了子会话 id**。
  验完已把测试用的子会话与账本条目清掉（工作区会话数回到 10）。

## 5. 现在能怎么用（真机操作指引）

```sh
# 1) 构建（改 host 代码后必须重启 profile；只改 client 代码刷新页面即可）

netstat -ano | findstr :3080     # 记下最后一列 PID
taskkill /PID <pid> /F
```

## 6. 已知限制与待裁决项

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 轮次标题是「第 N 轮」 | `adopt` 折轮次时只读轮次边界、**不读消息内容**，所以只能给通用名；只有「＋」新建的分支用提问首行当标题 | 可低成本改成「第 N 轮 · 提问首行」（`inspect` 已取事件前缀）——**待你决定** |
| `/branch/*` 未鉴权可达 | 无 cookie 也能调（官方 `/api/*` 无 cookie 是 401）。因 webserver 只绑 `127.0.0.1`，风险有限 | 需要裁决是否挂到带鉴权的传输上（测试计划 §0.3 路线 A） |
| 空会话/零事件会话只有"头" | 走官方 Agent 工厂后，**空会话也会落一个只有会话头的日志**（实测 372B），重启后仍在、可打开；它只是没有轮次，所以树上那个节点会一直是 `turn: null` 的占位（标题「新分支（待提问）」），跑完第一轮才升级成「第 1 轮」 | 已按官方语义处理；UI 上用占位标题引导用户去提问 |
| 重试窗口 15 秒 | 会话目录/导航面若 15 秒内仍未就绪，页面保留"未就绪"提示（点「刷新」可再试） | 当前足够；若将来服务启动更慢可加长 |
| 桌面端装法与重载 | `desktop` profile 由 Electron 独占：CLI 报 `managed exclusively by the Electron application`，只能在应用内插件管理器装（同一条受管管线的服务是 `ctx.pluginManager`）。装完**热应用、不用重启**；**改过 `lib/client.js` 也不用重启**（client-modules 会重新拉取热重载，实测重开面板即见新文案）。`Ctrl+R`/`F5` 无效，**F12 可开 DevTools** | 已写进测试文档 §11；导出因此改成 GET 下载地址（桌面下载的 `.tmp` 中间态见下条） |
