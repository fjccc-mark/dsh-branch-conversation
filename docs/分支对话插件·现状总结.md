## 1. 一句话结论

**插件已经在真机上跑通了。** 侧边栏出现「分支对话」行，中央列渲染出流程图页面，
打开一条会话就能把它的轮次自动折成节点树，切换会话会自动接入对应的树；
原先卡住整个真机验证的"路由不可达"阻塞点已定位为插件自身缺陷并修复。
**尚未验证的主要是"人点出来的交互"**（切换/折叠/文件节点/导出/孤儿升根）与桌面端。

**形态底线（管理员 2026-10-15 再次明确，验收第一条）**：
**分支对话必须是图形化界面**（竖向流程图表现节点树，不是纯文字列表），
且**能在对话的侧边栏里打开**（挂官方 `sidebar.panellist` 行 + `main` 中央列页，同一个 id 配对，
与官方面板行同栏共存可切换）。两项均已实现并通过真机截图确认；**余下只需人工在会话里确认一次**。
反例（不要走）：把流程图塞进 56px 侧边栏轨道；做独立窗口 / 独立 URL / 要开终端才能看的形态。

## 4. 已定位并修复的缺陷

### 4.1 真机轮次二（只有真机才会暴露）

一共 9 个，全部已修 + 有回归用例。按发现顺序：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 5 | `GET/POST /branch/*` → 裸 404 / 405（但 `register()` 成功） | 路由前缀注册成 `'branch'`（缺前导斜杠），webserver 的 `match()` 永不命中 | `BRANCH_ROUTE_PREFIX = '/branch'` |
| 6 | 路由通了但 `diagnostics` 变 500 `cannot get property "sessions" without inject` | Cordis 对**未 inject** 的服务属性访问会**抛错**（不是返回 undefined） | 新增 `serviceOf()`：先试属性、吞掉该错、再退 `ctx.get()` |
| 7 | 首次打开面板报 `storage.exists=false / writable=false`（假只读降级） | 存储根只在首次写入时才 `mkdir`，而诊断是当场探测 | `TreeStore.ensureRoot()` 启动时建一次 |
| 8 | `adopt`/`view`/`create` 全 501「会话控制面不可用」（诊断却说服务都在） | `sessionModelOf` 把 `controller.list` 摘出来保存；真机上它是 **typert Remote 方法**，脱离 `this` 调用即失败 | 保留服务对象，调用方一律 `model.controller.list(…)` 带 `this` |
| 9 | 在有历史的会话上第一次建分支，前面轮次整段丢失 | `createSession` 走"新树"分支时只 upsert 一个父节点，折轮次逻辑只有 `adopt` 有 | 抽出 `syncTurns()`，`adopt` 与 `create` 共用 |
| 10 | 浏览器报 **Failed to load plugins**：`loaded without registering "dsh-branch-conversation"` | 加载器外壳的 `id` 写成了**面板 id**；client-modules 用 `stripClientSuffix(registration.id)` 当注册键，而 boot 图那行的 id 是**包名** | 外壳 id 改为包名 `dsh-branch-conversation` |
| 11 | 面板一直「未找到主视图会话——会话目录服务不可用」 | `sessions` 服务由 `@deepseek-ai/dsh-api-session-controller` 的 `ClientSessions` 构造函数 `provide("sessions", …)` 提供，而它**比我们晚激活**；我们只在入口读了一次 | 依赖声明补 `@deepseek-ai/dsh-client-ui-session`；取不到就**重试**（每 500ms，最多 15s）+ 就绪后**自动唤醒**页面 |
| 12 | 红字「没有可用的会话切换入口 (uiWorkspace.openSession)」 | 同上是时序问题：`uiWorkspace` 由 `@deepseek-ai/dsh-client-ui-workspace` 激活后提供 | 同样的重试 + 唤醒；依赖声明补 `@deepseek-ai/dsh-api-workspace-controller` |
| 13 | `apply` 抛错被壳吞掉，界面只剩 `dsh-branch-conversation: failed`，无法定位 | 壳只报 fiber 状态，不打印异常原文 | 入口包一层：失败时把可读原因打到 `console.error` 与 `window.__DSH_BRANCH__`（诊断永久保留） |

> 上一轮（M2 收尾）另有 1–4 号真机 bug（产物路径、`config === null`、`inject` 位置、Node handler 签名），见测试文档 §6.2。

### 4.2 网页端形态量测轮（本轮）

这一轮把 `F-5` / `W-9.1`（窄屏不退化）从"人工拖窗口看"变成**可重复的自动量测**，顺带抓出 4 个真缺陷：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 14 | **`panel.css` 从来没到过浏览器**：真机上页面只有裸样式，`panel.css` 只被 `tools/preview/*` 引用 | 浏览器半产物是 `__ModuleLoader__.load({id, factory})`，加载器只取模块**导出**，不处理任何 CSS 副作用；`src/` 里没有任何地方 import 它 | 构建时由 `wrap-client-bundle.mjs` 把 `panel.css` 内嵌为 `window.__DSH_BRANCH_CSS__`，`src/client/style.ts` 在 `apply()` 时插成 `<style data-dsh-branch-style>`（幂等）；新增回归用例 |
| 15 | 窄屏下**整页横向溢出**（360px 布局宽实测溢出 116px） | 节点行宽度由内容决定 → 行内标题的 `max-width: 100%` 变成循环依赖 → 浏览器退回文字固有宽度；且页面各子块没有 `min-width: 0` | 行改 `width: 100%`；`.dsh-branch-page > *` 一律 `min-width: 0` + `overflow-x: hidden`；页面只允许纵向滚动 |
| 16 | 深树 10 层的轨道前缀本身就有 356px，**光缩进**就宽过 360px 的中央列 | `layoutTree` 每级都铺一个 3 字符轨道，深度不设上限 | 新增轨道压缩：超过 4 级只画 `⋯ ` + 末 4 级（末级分支符号一定保留）；新增单测 |
| 17 | 极窄容器里徽标与长标题把折叠三角/「＋」挤出容器（点不到） | 没有容器级适配：徽标、"第 N 轮"等辅助信息与操作按钮抢同一行宽度 | `container-type: inline-size` + `@container`：≤560px 隐去徽标、≤380px 收紧间距与按钮内边距（按钮仍 ≥14px 见方）；树容器 `overflow-x: auto` 兜底 |

另外修掉两个**只在工具里出现**的坑（写进了工具注释，避免下一个人再踩）：
"idempotency 判据过宽导致新产物被误判为已包装"（差点带缺陷过测）、
"假 `window` 只当函数形参，导致产物读不到 `window.__DSH_BRANCH_CSS__`"。

**三条经验值得固化**：

1. **假环境能"证明通过"，也能"固化缺陷"**——外壳 id 那个 bug 被旧冒烟断言钉住；`panel.css` 这个问题则是"预览页能看、真机没有"的典型（预览页用 `<link>` 直接引 CSS，把缺陷掩盖了整个 M0–M4）。
2. **不要相信"猜的 URL / 猜的服务名"**——`/plugins/<id>/client.js` 是猜的；`sessions`/`uiWorkspace` 的真实提供者要去官方产物里查 `provide()` / `super(ctx, "name")`。
3. **形态要用几何量测兜住**——"看起来没破版"不算证据；把"无横向溢出 / 行不超容器 / 按钮在容器内"写成断言，才能在每次改造后自动回跑 `F-5`。

## 5. 现在能怎么用（真机操作指引）

```sh
# 1) 构建（改 host 代码后必须重启 profile；只改 client 代码刷新页面即可）
npm run typecheck && npm run build && npm run smoke

# 2) 启动网页端（后台），从输出里取带 token 的 URL
dsh --profile web --port 3080 --no-open
```

在浏览器打开该 URL 后：

1. 侧边栏点「分支对话」→ 页面出现流程图与工具栏；
2. **打开一条有问答的会话**（或用当前会话）→ 节点自动出现（读的是 `retainedBy.mainView`）；
3. 点节点标题 → 切到该会话；点「▾」→ 折叠；点「＋」→ 在该轮次下开子对话；
4. 工具栏三个导出按钮 → 浏览器直接下载 JSON / Markdown / Mermaid。

**收尾（停服务）**：

```sh
netstat -ano | findstr :3080     # 记下最后一列 PID
taskkill /PID <pid> /F
```

**撤掉安装**：`dsh plugin --profile web remove dsh-branch-conversation`

## 6. 已知限制与待裁决项

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 轮次标题是「第 N 轮」 | `adopt` 折轮次时只读轮次边界、**不读消息内容**，所以只能给通用名；只有「＋」新建的分支用提问首行当标题 | 可低成本改成「第 N 轮 · 提问首行」（`inspect` 已取事件前缀）——**待你决定** |
| `/branch/*` 未鉴权可达 | 无 cookie 也能调（官方 `/api/*` 无 cookie 是 401）。因 webserver 只绑 `127.0.0.1`，风险有限 | 需要裁决是否挂到带鉴权的传输上（测试计划 §0.3 路线 A） |
| 空会话/零事件会话不落盘 | DSH 的会话在**有事件之后**才持久化；"不给提问地建分支"会留下重启即失效的节点（树里显示为悬挂） | 这是 DSH 既有行为；插件可在 UI 上提示，或要求必须带首句提问 |
| 重试窗口 15 秒 | 会话目录/导航面若 15 秒内仍未就绪，页面保留"未就绪"提示（点「刷新」可再试） | 当前足够；若将来服务启动更慢可加长 |
| 桌面端未验证 | `desktop` profile 由 Electron 独占，必须在应用内插件管理器安装；已装插件需重装/重载才会用上新产物 | 下一步按测试计划 §2 执行 `D-*` |
