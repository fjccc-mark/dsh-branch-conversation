## 一句话定义

一个面向 **DeepSeek Harness**（未来含网页版 DeepSeek）的对话管理插件：AI 学习时让主对话（问答主线）保持不动，可派生**子对话**追问子问题，并以树形结构把对话与文件组织起来，由插件统一管理。

---

## 目标与定位

- **目标平台**：DeepSeek Harness；未来将支持网页版 DeepSeek。
- **核心定位**：主对话不变，新建子对话追问其中子问题；插件负责主对话/子对话/文件的创建、关联与组织。

---

## 核心概念

| 概念 | 含义 |
| --- | --- |
| 主对话 / 轴线 | 按时间顺序串联管理员与 AI 轮次的主线，始终保持原样。 |
| 节点 | 主对话中，AI 的每一次回复（「替我」）作为一个节点挂在轴线上。 |
| 子对话 | 追问的子问题，以**树形结构**挂接到对应主对话节点上，可递归派生。 |
| 文件节点 | 文件可作为节点挂载到任意节点（主/子）上，与对话节点同级。 |

---

## 功能详述

### 1. 会话管理（数据结构）

- 主对话即一条「轴线」，按时间顺序串联轮次；AI 的每次回复为一个节点。
- 子对话以树形挂接到对应主节点；树可递归，子节点本身还能再派生子对话。
- 结构示意：
  - 主轴线：节点1 ─ 节点2 ─ 节点3 ─ …
  - 节点2 ┬ 子对话A（树）
          └ 子对话B（树）
          └ 文件节点C
- 插件职责：维护轴线顺序、节点父子归属、子树展开/收起、跨节点引用。

### 2. 文件节点（挂载）

- 可将文件作为节点挂载到树结构的任意节点上（主对话节点或子对话节点均可）。
- 文件节点与对话节点同级，参与轴线/树形渲染与定位。
- 用途：把参考资料、产出物、上下文文档直接挂到对应讨论分支，便于追溯。

### 3. 图形界面（渲染）

- 轴线 + 树形结合：横向时间轴为主轴线，主节点沿线排列；子对话以树状分支从节点展开并可折叠。
- 主对话连续可见，点击节点展开其子树。
- 支持定位：点击任意子对话节点，跳回对应主对话上下文。

### 2026-10-14（第二轮：裁决与澄清）
- **节点定义修正**：节点 = **一次提问 + 一次回答**（原「AI 的每一次回复」作废）；节点身份 = 该会话中的 **turn**。
- 子对话 = 在父对话某节点上提出新问题而**新建的会话**；**不继承对话上下文**，只继承模型/人设/权限（= 同 `agentPreset`）。
- 存储独立于 DSH；**每棵树一把锁**。
- 不收束、不回流；主对话不变仅指**其上下文不变**。
- 父会话被删除时：该节点的**整棵子树作为一棵新的独立树升为根**，树形不改写；该节点上的文件引用删除。
- 界面形态：官方侧边栏中的**一个可切换页**，流程图展示节点关系，点击节点切换会话；文件用官方预览打开。
- 导出：JSON + Markdown + Mermaid 三种。
- 节点边界：被打断的轮次仍算一个节点；**模型自己调用的子智能体不算**。
- 命名：`dsh-branch-conversation`，显示名「分支对话」。
- 网页版 DeepSeek 支持**降为待评估**。

### 2026-10-15（第三轮：把「图形化」的口径钉死）
- 管理员明确：**「图形化界面需要显示可视化的流程图节点联系，类似 visio 渲染的流程图」**。
- 解读：**图形化 = 节点框 + 连线**的实景流程图。这与原裁决 **B1/B5**（以流程图形式显示节点关系）
  与 **B10**（轴线 = 一个对话中多次问答节点**连成的线**）一致——之前把"流程图"实现成
  "缩进 + `│├─ └─` 轨道字符的竖向列表"是**理解偏窄**，它没有"框"也没有"连线"。
- 因此要求：
  1. 节点渲染成**有边框的框**（轮次号 / 标题 / 状态点 / 折叠把手 / 「＋」）；
  2. 父子节点之间**画出来的连线**（端点贴框边缘），同一会话相邻轮次的**轴线也可见**；
  3. 位置是**二维坐标**（同级节点成行），不是单列堆叠；
  4. 折叠后后代与连线消失、**剩余节点重排**；
  5. 窄屏下画布**双向滚动 + 可缩放**，仍是"框 + 线"，不退化回列表。
- 落地口径见 [设计文档 §3.2](分支对话插件·设计文档.md)（实现选型）、
  [完善计划 §5.5](分支对话插件·完善计划.md)（形态基线 F-3/F-4/F-8 与新增里程碑 **M6**）、
  [测试计划 §0.5](分支对话插件·测试计划.md)（可判定口径与反例）。
