## 0. 需求与已拍板的口径

**需求（2026-10-16）**：在**保持原有功能不变**的前提下，增加"可以在**右侧侧边栏**打开分支对话"。

**已拍板（2026-10-17，用户确认）**：

| # | 决定 | 影响 |

## 1. 官方标准复核（本轮重点）

**复核依据**（按 skill 规定的资料优先级）：

1. **官方专题文档**：skill 知识库 `references/official-docs/docs/subsystems/sidebar-right.md`（158 行，权威契约）；
2. **官方包 README**：从宿主 `app.asar` 里直接取出 `@deepseek-ai/dsh-client-ui-sidebar-right` 的
   `README.md`（26 KB）与 `package.json` —— 版本 **0.2.0-rc.2**，与本机 `dsh --version` 一致；
3. 官方示例代码（专题文档内 `image` 类型范例）与 `dsh-client-ui-deliverables` 的真实注册形状。

### 1.1 键位：用户说的就是官方默认（`sidebar.right.toggle`）

```js
defaults: {
  "desktop:windows": { code: "KeyB", modifiers: ["primary", "alt"] },   // Ctrl+Alt+B
  "web:windows":     { code: "KeyB", modifiers: ["primary", "shift"] }  // Ctrl+Shift+B
}
```
→ **不自己绑键**：键位属于官方；我们只是把页签挂进去。

### 1.2 页签 = 两处注册（官方原文）

> A tab type registers in two stages … Both stages sit inside the type's own `ctx.effect`, so the
> registration lives exactly as long as the plugin that made it.

```ts
// ① 类型（静态声明，无运行时钩子）
ctx.effect(() => ctx.sidebarRightTabs.register({
  id: 'dsh-branch-conversation',      // 本实现在页签系统里的身份，全局唯一；也是内容座位的 key
  kind: 'branch-conversation',        // 类型判别式；openTab 用这个名字
  priority: 'extension',              // 默认值；产品外类型最高档
  title: () => '分支对话',             // chip 文案；开页签时捕获一次
  guide: { order, title, description, icon }  // 让官方"引导页"能列出一个入口（可选但建议）
}), 'branch-conversation type')

// ② 内容（keyed 座位，按 definition.id 分派）
ctx.effect(() => ctx.slots.inject('sidebar.right.pane.tab', () => ctx.slots.register(
  { name: 'sidebar.right.pane.tab', key: 'dsh-branch-conversation' },
  BranchTabBody,
)), 'branch-conversation body')
```

### 1.3 ⚠️ 修订一：**页面型页签不写 `patterns`，地址由官方自己写**（原计划这里错了）

官方原文两条：

> A **page address** is what the Sidebar records for a tab opened by kind rather than by resource:
> `sidebar://<kind>`, **written by the Sidebar itself** when `openTab(kind)` runs.
> **Callers never build one** … and no other navigation address exists.

> A **page type** — the guide, a file tree — **names none** [`patterns`] and is opened by kind.

- **原计划（错）**：自定 `dsh-resource://branch-conversation/<treeId>` 地址 + `patterns` + `canOpen`。
  页签打开时必须 `openResource`，而它只接受 `dsh-resource://` 且**必须有对应的 `ResourceProtocolMap` 协议提供者**
  （`ctx.resources.register`）——为一个纯页面型页签引入资源协议是**多余的机制**，还会把"当前会话"的语义
  硬塞进地址里。
- **修订后（对）**：**页面型**：不写 `patterns`/`canOpen`，用 `ctx.sidebarRight.openTab('branch-conversation')`；
  地址 `sidebar://branch-conversation` 由官方自己记账。
  「当前会话所在的树」不需要靠地址表达——**内容座位是 `session` 作用域**，body 天然拿到当前会话（§1.4）。

### 1.4 ⚠️ 修订二：body 的输入是 `useTabInfo()`，会话作用域直接给到 `sessionId`

官方原文：

> The body — `ctx.slots.register({ name: 'sidebar.right.pane.tab', key: definition.id }, Body)`
> reads `{ sidebar, panel, tab }` through the framework-injected **`useTabInfo()`**.
> `sidebar` supplies expansion and fullscreen; `panel.id` identifies its pane;
> `tab` contains the record fields, `visible`, `navigation`, `signal`, and `actions`.

- `sidebar.right.pane.tab` 的 scope 是 **session**（skill 的 `slots.md`：`session` = 需要已解析的 Provider 绑定、
  并收到确定的 Session 值）→ body 是 **session 作用域组件**，直接拿当前会话，**不用自己猜/订阅当前会话**。
- `tab.actions` 提供 `openResource` / `openTab` / `close`，且**已绑定该页签自己的会话**。
- **修订**：原计划写的是"薄壳自己 `branchApi.adopt` 拉树"，需要改成：
  用框架给的会话作用域输入定位"当前会话 → 它的树"，再复用既有 `branch-api` 取视图数据；
  缩放/滚动继续走既有的 `view-state.ts`（`tab.actions` 与 `useTabInfo` 不能替代它）。

### 1.5 ⚠️ 修订三：**服务在没有会话时会抛**——每次调用前都必须守卫

官方原文：

> `openResource` … `openTab` … **throw** rather than write into a surface nobody draws.
> **`mounted`** is the observable of the Session on screen … `undefined` while a global panel replaces it
> or no Session is selected.

> **No surface without a session.** State is keyed by session id, so the hero screen shows nothing on the right.

- **`openTab` 在"没有会话"或"服务没注册"时都抛**（前者是运行时状态，后者是接线错误）。
  「在右侧打开」按钮**绝不能**直接调它：必须先判断 `mounted` 有值，再调；否则**按钮禁用 + 说明**。
- 这正好也是**降级路径**：服务缺失/无会话 → 不抛、可见地禁用（F-12 验这条）。

### 1.6 ⚠️ 修订四：`patterns` 那套 `canOpen` 与 `title` 的语义要写清楚

- `title(address)` **只在开页签时捕获一次**（官方"Titles are fixed at open time"）；要**实时标题**得再注册
  `sidebar.right.pane.tab.title` 座位。我们这个标题是固定的（"分支对话"），**不需要**标题座位——省一处注册。
- `guide` 字段（`{ order, title(), description?(), icon? }`）是**官方引导页的入口盒子**：
  用户在官方"引导页"上能看到「分支对话」并点开。**建议提供**（这正是"用官方键位打开右侧栏后能找到我们"的路径）。
- `keepMounted: true`（可选）：让 body 在隐藏、切会话、停靠之间**保留挂载**——对我们的缩放/滚动是**额外**收益，
  但会带来"后台会话也持有"的代价，**M7.1 先不开**，等 F-11 实测后再定。

### 1.7 `dsh.client.inject` 要补哪一个（**先弄清"谁提供座位"**）

官方右侧包的 `package.json`（从 asar 取出，版本 0.2.0-rc.2）：它是 **client-only**（`lib/index.js` 是空 host half）。

```json
"dsh": { "client": { "inject": ["@deepseek-ai/dsh-api-session-controller",
  "@deepseek-ai/dsh-client-resources", "@deepseek-ai/dsh-client-ui-conversation",
  "@deepseek-ai/dsh-client-ui-layout", "@deepseek-ai/dsh-client-ui-session",
  "@deepseek-ai/dsh-client-shortcuts"], "platform": "web" } }
```

**但注意它 inject 列表里没有 `ui-renderer`**——而 `ctx.slots` 恰恰不是右侧包提供的。
从 asar 取出的官方 `@deepseek-ai/dsh-client-ui-renderer/package.json` 自述是：

> Browser UI renderer: **React slot bindings**, `ctx.uiRenderer`, and the assembled application root
> —— `dsh.client: { platform: "web", immediately: true }`（`immediately: true`：它在启动时立刻加载）

所以我们真正依赖的"座位提供者"是 **`@deepseek-ai/dsh-client-ui-renderer`**，右侧包只是新增的座位**拥有者**。

| 要补进 `dsh.client.inject` | 理由 |
| --- | --- |
| `@deepseek-ai/dsh-client-ui-sidebar-right` | M7 新增：右侧座位的拥有者，也是加载顺序依据（**只 client 侧**，它是 client-only 包） |
| `@deepseek-ai/dsh-client-ui-renderer` | **既有缺口**：`ctx.slots` 的真正提供者；不声明它，我们的座位注册就没有先后保证（只能靠轮询兜） |
| ~~`@deepseek-ai/dsh-client-locale`~~ | 既有列表里有多余项：我们**没有**用 locale 服务（见 §4.6） |

> 仍然保留**运行时探测 + 优雅降级**：包没装/没激活时 `ctx.get('sidebarRightTabs')` 是 undefined，
> 我们不能让整个 `apply` 挂掉——skill 明确警告 host 插件 `apply()` 抛错在 `dsh web` 下**可能完全不可见**，
> 只表现为工具/监听器静默缺失。声明 `inject` 是为了顺序与语义，不是为了省掉探测。

### 1.8 `ctx.inject([...], cb)`：官方推荐的"可选服务"写法

skill 原文：

> 可选服务放进 `inject` 或 **`ctx.inject([...], ...)`**，这样在没有它们的 profile 里**插件保持不激活，而不是抛错**。

→ 右侧那两处注册放进一个 `ctx.inject(['slots', 'sidebarRightTabs'], cb)`：
服务齐了才注册页签类型；不齐就整块不激活（左侧功能不受影响）。这比"先注册再补救"更贴官方。

### 1.9 `guide` 入口的**精确形状**（不写对，F-9 必然失败）

官方实现产物里的原文（`dsh-client-ui-sidebar-right/lib/client.js`，`SidebarRightTabRegistry.register`）：

```js
const entries = definition.guide ?? [];
if (new Set(entries.map((entry) => entry.id)).size !== entries.length)
  throw new Error(`sidebarRight: duplicate guide entry id in "${id}"`);
```
```js
this.guideEntries = this.cached
  .flatMap((definition) => (definition.guide ?? []).map((entry) => ({ ...entry, kind: definition.kind, providerId: definition.id })))
  .sort((left, right) => left.order - right.order);
```

由 `?? []` + `flatMap` + `order` 排序 + **按 `id` 查重**可确定：

- **`guide` 是一个数组**（不是单个对象）；每个条目**必填 `id`**（在同一 provider 内唯一）与 **`order`**（排序键）；
  `title()` 与可选 `description()`/`icon?` 是渲染用文案；
- **省略 `guide`（`Omit to stay off it`）就等于不出现在官方引导页**——而 F-9 的验收路径正是"用官方键位打开右侧栏 → 在引导页上找到入口"，
  所以 **M7.1 必须写 `guide`**，否则 F-9 必红；
- 引导页列表的**渲染座位是 `sidebar.right.tab.guide.entry`**（官方自带 fallback 卡片，**第三方不必注册它**）；
  `sidebar.right.tab.menu.item` 是**另一套**（页签内容级动作菜单），**不是**入口。入口只有一个正确做法：**定义里写 `guide`**。

### 1.10 ⚠️ 根因级契约缺陷：具名导出与 `export default` 混用会把 `inject` 静默丢掉（**M7.0 必须先修**）

这条不是右侧栏特有的，但它**决定 M7 能不能按官方方式写**，所以必须在计划里说清。

**官方条款**（skill §3.1）：

> Host 插件导出形态（**不要混用**）：`export function apply(ctx, config) {}` + 可选 `export const inject = [...]` + `export const Config`；
> **或者**一个 service class 作为 default export。

**我们的现状**（我自己核对过产物，不是转述）：

| 产物 | 末尾导出 | 含 `.default` |
| --- | --- | --- |
| 官方 `ui-sidebar-right/lib/client.js` | `exports.apply = apply; exports.inject = inject;` | **否** |
| 官方 `ui-deliverables/lib/client.js` | 同上（只有 2 行 exports） | **否** |
| 官方 `ui-sidebar-documentpreview/lib/client.js` | 同上 | **否** |
| **我们 `lib/client.js`** | `exports.apply = apply; exports.default = apply; … exports.inject = inject;` | **是** |
| **我们 `lib/index.js`** | `export { …, apply, apply as default, …, inject, … }`（宿主侧同样混用） | **是** |

loader 会先"解包"模块命名空间：`exports = exports.default ?? exports`。
官方包**没有** `.default` → 解包后仍是那个带 `inject` 的对象 → **`inject` 生效**；
我们有 `.default`（且等于裸 `apply` 函数）→ 解包后**只剩裸函数**，`inject` / `Config` / `name` **全部丢失**。

**后果**：我们声明的 `inject`（宿主侧 `['webServer']`、客户端侧 `['slots','sessions']`）**从未生效**，
服务晚到只能靠既有的"鸭子类型 + 轮询 + 手写默认值"兜——那正是仓库里 `withDefaults()` 与各种 `retry*` 的由来。

**修法**：**去掉 `export default apply`**，只保留具名导出（与官方三例一致）。
改完 `lib/client.js` 与 `lib/index.js` 都应变成"只有具名导出、没有 `.default`"（可用产物断言钉死）。

**为什么放进 M7.0**：M7.1 要用 `ctx.inject([...], cb)` 一次写对；若 `inject` 仍被丢弃，
`ctx.inject` 的门控就形同虚设，右侧注册会退回到"轮询 + 祈祷"。**先修根因，再挂页签。**

### 1.9 UI 硬规定（skill 红线，逐条对我们的现状核过）

| 规定 | 我们现状 | 结论 |

## 2. 目标行为（做完之后是什么样）

1. **左侧一行都不变**：`sidebar.panellist` 的「分支对话」行 + `main` 里的画布页照旧（F-1/F-2/F-6 断言仍须全绿）。
2. **右侧多一个页面型页签**：`kind = branch-conversation`，内容 = **同一个画布**（同一套 `layoutTree` + 节点框 +
   SVG 连线 + 折叠/缩放/滚动）。
3. **三条打开路径**（都不需要用户学新东西）：
   - 官方键位打开右侧栏（web `Ctrl+Shift+B` / 桌面 `Ctrl+Alt+B`）→ 官方**引导页**上出现「分支对话」盒子（靠 `guide` 字段）；
   - **左侧画布工具条上的「在右侧打开」按钮**（已拍板要做）→ `openTab('branch-conversation')`，官方在**同一步**里展开该列；
   - 右侧页签里继续操作（折叠/缩放/点节点/「＋」），行为与左侧一致。
4. **显示"当前会话所在的树"**：页面型页签 + session 作用域 body；没有会话时**不显示面板也不报错**（官方行为）。
5. **纯本地、无新依赖、不改官方、不改树文档**。

## 4. 实现要点

### 4.1 新文件 `src/client/right-sidebar.ts`

```ts
/** 页签种类：openTab 用这个名字；也是官方记的地址 `sidebar://branch-conversation` 的来源。 */
export const BRANCH_TAB_KIND = 'branch-conversation'
/** 本实现在页签系统里的身份：全局唯一，同时是内容座位的 key。 */
export const BRANCH_TAB_ID = 'dsh-branch-conversation'

/** 类型定义（页面型：**不写 patterns / canOpen**；见 §1.3）。 */
export function branchTabDefinition(label: string): {
  id: string
  kind: string
  priority: 'extension'
  title(): string
  /**
   * 官方引导页的入口盒。**数组**、每项必填 `id` 与 `order`（见 §1.9）。
   * 不写它就等于不出现在引导页 —— F-9 会因此失败。
   */
  guide: readonly { id: string; order: number; title(): string; description?(): string }[]
}

/**
 * 装两处注册；服务不全时返回 false（**不抛**）。
 * 内部用 ctx.inject(['slots', 'sidebarRightTabs'], …) 让"缺服务"表现为整块不激活。
 */
export function installRightSidebar(ctx: unknown, renderBody: unknown): boolean

/** 打开/聚焦当前会话的页签。无会话（mounted 为 undefined）或服务缺失时返回 false，绝不抛。 */
export function openBranchTab(): boolean

/** 「在右侧打开」按钮是否可用（服务在 + 有会话）。 */
export function canOpenBranchTab(): boolean
```

### 4.2 画布复用（**不复制粘贴渲染逻辑**）

从 `panel.tsx` 把 `BranchCanvas` / `NodeBox` 导出，右侧 body 用一个薄壳包它：

- **会话来源不同**：左侧页面自己解析"当前会话"（既有 `use-main-session.ts`）；右侧 body 是 **session 作用域**，
  由框架给出当前会话（§1.4）。薄壳把两者归一到同一个入参，再交给同一个 `BranchCanvas`。
- **视图状态**：继续用 `view-state.ts`。注意 F-6 的语义是"跨面板切换存活"——右侧页签是**另一个座位**，
  共用同一份视图状态意味着左右缩放/滚动一致；若实测发现"右栏窄、缩放不合适"，再给右侧单独一份
  （`view-state` 已经是模块级单例，加一个 key 即可，属小改）。

- 不新增 npm 依赖、不改官方包。

### 4.5 样式合规整改（M7.0 的具体做法）

现状：`--dsw-alias-*` token 引用 **0**、硬编码 hex **3**、`rgba()` **18**。整改口径：

| 现状 | 改成 |
| --- | --- |
| `rgba(...)` 做的边框/背景/阴影 | 对应 `--dsw-alias-*`（边框、填充、浮层 token） |
| `#d97706`（孤儿/缺失状态点）与 `#16a34a` | 先查官方 `Theme` 有哪些语义色 token；能对上就用 token；对不上则**保留为 artwork 级字面色**并在注释里写明理由 |
| 连线颜色（主轴实线 / 分支虚线） | 这类"语义图形色"若没有对应 token，也按 artwork 处理并注明 |

> skill 的取舍很明确：**token 是唯一共享样式依赖**；token 改名最多让外观退化、**永远不会弄坏渲染**。
> 所以能换的都换；确实属于"图形语义"的少数几个字面色，留注释说明。

### 4.6 文案与展示元数据（M7.0）

- **展示元数据（必须补）**：`locale/en.json`、`locale/zh.json` 里写 `meta.title` / `meta.description`，
  `package.json` 的 `files` 补 `locale`，并导出 `./locale/*.json`；`icon.svg` 已存在（≤256 KiB，realpath 在包内）。
  Plugin Manager / Settings 会在**不激活**插件的前提下读这些。
- **运行期文案是否迁到 `ctx.locale`**：现状是硬编码中文，且**没有**注册 locale 命名空间。
  迁到 locale 服务是官方推荐做法（"可见文案走 Client locale"），但它是**横跨全部 UI 文案**的改动，
  与"右侧栏"不是同一件事。建议：**M7.0 只补展示元数据**；运行期文案是否迁移**单独立项**（列入待裁决），
  避免本轮混入大面积文案改动。

## 9. 实施结果（2026-10-17）

**已完成**：M7.0（0a 导出形态 / 0b 样式 token 化 / 0c 展示元数据 / 0d inject 校正）、M7.1（页面型页签 + `guide` + 右栏画布）、M7.2（左侧「在右侧打开」按钮）。
**实测**：`npm run smoke` **111/111**（新增 `right-sidebar.mjs` 11 条 + 产物层的紧凑表单标记）、`layout-shots` **88/88**、
`served-bundle` 通过（线上产物 81,090 字符）、`real-machine` **F-1~F-10 全绿**（含官方键位真发、引导页入口、
右栏渲染 9 框、切回对话后开页签、再切回缩放仍在）。

**实施中发现、计划里没料到的三件事**（都已修，详见测试文档 §9.2）：

1. 官方右侧服务**比我们晚激活** → 入口要重试（500ms × 最多 15 秒），装不上只记诊断；
2. 诊断位不能冒充失败（`failed` 与 `rightSidebar` 分开），否则"插件注册成功"断言会误红；
3. **官方右侧详情列是按会话的**：全局面板（我们自己的页面）占着中央列时 `mounted` 为 `undefined`，`openTab` 会抛
   → 「在右侧打开」必须先 `ctx.layout.selectPanel(null)` 切回对话、等一拍再开页签，并对 `openTab` 包 try/catch。

**F-11 ~ F-13 也已补测通过**：右栏内缩放/折叠生效（共用同一画布组件、树只有一份）；hero 屏点按钮不崩并给出可读提示（`[data-dsh-branch-right-notice]`）；亮/暗两态下节点底色 `rgb(255,255,255)` → `rgb(44,44,46)`，证明 `--dsw-alias-*` token 真的生效（截图 `theme-light.png` / `theme-dark.png`）。

**F-14（2026-10-17 追加，已通过）**：右栏里点「＋」不再只是"请去左侧"，而是就地弹出**紧凑表单**
（`BranchCreateForm compact`：标题 + 一句轮次说明 + 两行提问 + 两个按钮，轮次固定为被点的那个框）——
右栏默认只有约 320~420px，页面那版表单摆不下。真机 UI 探针：右栏点「＋」→ 填首句 → 提交后
**右栏画布框数 +1**、新连线起点 = 被点的框、树 id 不变、表单收起并给出可读状态、地址未变。
产物层兜底：`client-bundle.mjs` 断言标记在产物里、`served-bundle.mjs` 断言线上产物含标记。

**唯一细节**：右栏里"点击节点切会话"未单独点过（左侧有人工项覆盖）。
