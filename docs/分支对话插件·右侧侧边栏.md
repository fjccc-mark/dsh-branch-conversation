# 分支对话插件 · 右侧侧边栏（详情列）支持 · 实施计划

> 用途：把"**也能在右侧侧边栏打开分支对话**"这件事拆成可执行、可验收、可回滚的步骤。
> 状态：**计划待批，尚未开工**（本文件只写方案与口径，不改代码）。
> 制定时间：2026-10-16。前置：[进度快照](进度快照.md) · [设计文档](分支对话插件·设计文档.md) §3.1 · [测试计划](分支对话插件·测试计划.md) §0.5（形态门 `F-*`）。
> 一句话：**左侧侧边栏那套（行 + 中央列页）完全不动**，另外把同一个画布再挂到官方"右侧侧边栏（详情列）"的一个页签上。

---

## 0. 需求与非目标

**需求（用户 2026-10-16 提出）**：在**保持原有功能不变**的前提下，增加"可以在**右侧侧边栏**打开分支对话"的能力。
用户对"右侧侧边栏"的定义：**网页版 `Ctrl+Shift+B`、桌面版 `Ctrl+Alt+B` 打开的那一栏**。
→ 这与官方实现**完全吻合**（§1.1 的键位全表就是这两个组合），所以口径没有歧义。

**非目标（本轮明确不做）**：

| 不做 | 原因 |
| --- | --- |
| 把左侧侧边栏那一行/那页去掉或改变行为 | 用户明确要求"保持原有功能不变"；左侧仍是主入口 |
| 自造一套右侧面板（自己画列、自己绑键） | 官方已有右侧侧边栏与键位，自造会与官方争抢 `Ctrl+Shift+B`，也会破坏布局/响应式 |
| 修改主对话内容、树文档结构 | 与既有裁决（A4/A5/B4）一致：插件不改写会话，树结构不因"在哪显示"而变 |
| 右侧支持"多棵树各占一个页签" | 见 §3.3 的分期：先做"一个页签显示当前会话的树"（M7.1），多页签留作 M7.3 可选 |

## 1. 取证（都是实测，不是猜）

**取证方式**：官方包在 `app.asar` 里（打包二进制，本仓库 `node_modules` 没有），但真机会把它们的
客户端产物当**纯 JS** 发给浏览器。于是启动一个 `web` profile，把 boot 清单里各插件的产物拉下来读源码。
（脚本是临时的，用完即删；下方引用的是产物里的原文片段。）

### 1.1 键位：用户说的就是官方默认

`@deepseek-ai/dsh-client-ui-sidebar-right` 产物里 `registerSidebarShortcuts()` 的原文：

```js
shortcuts.register({
  id: "sidebar.right.toggle",
  label: () => t("command.toggle"),
  aliases: ["right sidebar", "toggle right panel"],
  defaults: {
    "desktop:macos":  { code: "KeyB", modifiers: ["primary", "alt"] },
    "desktop:windows":{ code: "KeyB", modifiers: ["primary", "alt"] },
    "desktop:linux":  { code: "KeyB", modifiers: ["primary", "alt"] },
    "web:macos":      { code: "KeyB", modifiers: ["primary", "shift"] },
    "web:windows":    { code: "KeyB", modifiers: ["primary", "shift"] }
  },
  regions: ["page", "editable", "terminal"],
  ...
})
```

→ **web:windows = Ctrl+Shift+B**、**desktop:windows = Ctrl+Alt+B**（`primary` 在 Windows/Linux 上是 Ctrl、macOS 上是 Cmd）。
与用户描述完全一致；**这个键位是官方的，我们只是"把页签挂进去"，不需要也不应该自己绑键**。

### 1.2 右侧侧边栏是**可扩展**的：官方给了页签座位与服务

| 东西 | 名字 | 说明 |
| --- | --- | --- |
| 页签**类型**注册表 | `ctx.sidebarRightTabs.register(definition)` | 插件声明"我这种页签长什么样" |
| 页签**内容**座位 | `slots.register({ name: "sidebar.right.pane.tab", key: <你的 id>, … })` | 按 kind 分派的 keyed 座位 |
| 页签**活动标题**座位 | `slots.register({ name: "sidebar.right.pane.tab.title", … })` | 标签上的实时标题 |
| 导航面 | `ctx.sidebarRight.openTab(kind, options)` / `openResource(address, options)` / `close()` / `focus()` | 打开/聚焦页签 |
| 关闭前清理 | `ctx.sidebarRightTabs.registerCloseHandler(kind, handler)` | 资源清理（每个 kind 只能注册一次） |
| 引导页座位 | `sidebar.right.tab.guide(.entry)`、`sidebar.right.tab.menu.item` | 官方"右侧空白页"里列可打开的页签 |

官方原话（产物注释）：

> Tab bodies do not live here. Each one is a registration under its type's kind, dispatched through the keyed
> `sidebar.right.pane.tab` seat (and a live chip title through `sidebar.right.pane.tab.title`),
> so **a new tab type needs no edit to this file**.

→ 也就是说：**官方明确支持第三方插件往右侧加页签**，而且不需要改官方代码。

### 1.3 官方范式：`dsh-client-ui-deliverables`（照抄它的形状）

它是官方自己的右侧页签插件，产物里的关键两行：

```js
// ① 声明页签类型
function changesReviewDefinition(t) {
  return {
    id: "@deepseek-ai/dsh-client-ui-deliverables",   // 插件身份（也是内容座位的 key）
    kind: "changes-review",                          // 页签种类
    patterns: ["dsh-resource://changes-review/**"],   // 它能处理哪些地址
    priority: "builtin",                             // 档位：extension | builtin | fallback
    canOpen: (address) => parseChangesReviewAddress(address) !== undefined,
    title: (address) => { /* 实时标题 */ }
  }
}
ctx.effect(() => ctx.sidebarRightTabs.register(changesReviewDefinition(t)), "…")

// ② 注册页签内容（keyed 座位）
ctx.slots.inject("sidebar.right.pane.tab", () => ctx.slots.register({
  name: "sidebar.right.pane.tab",
  key: CHANGES_REVIEW_ID,
  locale: NS,
  inject: () => ({ hooks: { … } })
}, ReviewTab))

// ③ 打开它
ctx.sidebarRight.openResource(changesReviewAddress(coordinates), { params: { index } })
```

它的依赖声明（我们要照着写）：

```js
const inject = ["slots", "locale", "uiConversation", "remote", "remote.session",
                "sidebarRightTabs", "sidebarRight", "configForms"]
```

### 1.4 我们仓库的现状（影响实施方式）

| 事实 | 影响 |
| --- | --- |
| 本仓库 `node_modules` **没有** `dsh-client-ui-sidebar-right` / `-shortcuts` / `-dockkit` / `-deliverables`（公开 npm 线未发布） | 实施时**不引新依赖**：照仓库既有风格，用**鸭子类型 + 形状探测**访问 `sidebarRightTabs` / `sidebarRight`（与 `slots`、`sessions`、`uiWorkspace` 的做法一致） |
| `package.json` 的 `dsh.client.inject` 目前列了 7 个官方包 | 需要**补一个** `@deepseek-ai/dsh-client-ui-sidebar-right`——否则 `ctx.sidebarRight*` 拿不到（Cordis 里未 inject 的服务属性访问会**抛错**，这条本仓库踩过并写进测试文档 bug #6） |
| 左侧那套（`sidebar.panellist` 行 + `main` keyed 页）已实现且已验证（F-1/F-2/F-6） | **一行都不用改**；新能力是"同一个画布组件换个座位再挂一次" |

> ⚠️ 仍待实施期首验的两个点（写在这里，避免把它们当"已知"）：
> ① 右侧页签是**按会话（per-session）**存的（证据：`navigator.openTabIn(sessionId, …)`、`this.session(sessionId)`），
>    所以"插件被激活时自动开一个页签"要看**当前有没有会话**——没会话时应当**什么都不做**（不能报错）；
> ② `sidebar.right.pane.tab` 是 keyed 座位，**一个 kind 一个 key**；
>    "同一 kind 能否开多个页签"由定义里的字段控制（官方代码里出现过 `multiple` 与 `keepMounted`），
>    M7.1 不需要它，M7.3 再去核准。

## 2. 目标行为（做完之后是什么样）

1. **左侧一行都不变**：`sidebar.panellist` 的「分支对话」行 + `main` 里的画布页照旧（F-1/F-2/F-6 的断言仍须全绿）。
2. **右侧多一个页签类型**：kind = `branch-conversation`，内容 = **同一个画布**（同一套 `layoutTree` + 节点框 + SVG 连线 + 折叠/缩放/滚动）。
3. **两种打开方式**（都不需要用户学新东西）：
   - 用官方键位打开右侧栏（web `Ctrl+Shift+B` / 桌面 `Ctrl+Alt+B`），在右侧的**引导页/加号菜单**里能看到并可点开「分支对话」
     （官方把可打开的页签列在 `sidebar.right.tab.guide.entry` / `sidebar.right.tab.menu.item` 这些座位上）；
   - 在**左侧**画布的工具条上给一个「在右侧打开」按钮：点了就 `ctx.sidebarRight.openTab('branch-conversation')`
     ——顺便把右侧栏展开（官方 `openWithFocus` 的语义）。
4. **状态与左侧一致**：右侧页签显示的是**当前会话所在的树**；折叠/缩放/滚动沿用第 4.5 节那套视图状态语义
   （M7.1 先做到"同一份视图状态"，即左/右切换不丢；右侧独立记忆列为可选项）。
5. **纯本地、无新依赖、不改官方**：不新增 npm 依赖、不自造面板、不改主对话与会话头。

## 4. 实现要点（照抄官方 + 本仓库既有风格）

### 4.1 新文件 `src/client/right-sidebar.ts`

```ts
/** 页签种类：与官方 kind 命名一致（小写连字符）。 */
export const BRANCH_TAB_KIND = 'branch-conversation'
/** 插件身份：同时也是内容座位的 key（官方范式：deliverables 用的就是包名）。 */
export const BRANCH_TAB_ID = 'dsh-branch-conversation'

/** 地址：`dsh-resource://branch-conversation/<treeId | sessionId>`。 */
export function branchAddress(treeIdOrSessionId: string): string
export function parseBranchAddress(address: string): { key: string } | undefined

/** 页签类型定义（官方 `changesReviewDefinition` 的同形状）。 */
export function branchTabDefinition(): {
  id: string; kind: string; patterns: string[]; priority: 'extension'
  canOpen(address: string): boolean
  title(address: string): string
}

/** 把"类型 + 座位"挂进去；服务缺失时返回 false（自然降级，不抛）。 */
export function installRightSidebar(ctx, renderPage): boolean

/** 打开/聚焦当前会话的页签；服务缺失或没有会话时返回 false。 */
export function openBranchTab(): boolean
```

**形状探测**（与 `serviceOf()` 同款，因为未 inject 的属性访问会抛）：

```ts
const tabs = serviceOf<{ register(def: unknown): () => void }>(scope, 'sidebarRightTabs')
const right = serviceOf<{ openTab(kind: string, options?: unknown): void }>(scope, 'sidebarRight')
```

### 4.2 画布复用（关键：**不复制粘贴渲染逻辑**）

现在 `BranchPanelPage` 是"页面 + 画布 + 工具条 + 自检 + 建分支表单"的一整块。右侧页签只需要**画布那部分**。
做法（推荐，改动最小且不伤左侧）：

1. 从 `panel.tsx` 里把 `BranchCanvas` / `NodeBox` **导出**（它们已经是独立函数组件）；
2. 新增一个**薄壳** `BranchCanvasPane`：自己拉树（`branchApi.adopt`）+ 渲染 `BranchCanvas` + 复用同一套
   `view-state`（缩放/滚动）+ 折叠/建分支/开文件这几个动作；
3. 左侧页面继续用 `BranchPanelPage`（它内部也改成用 `BranchCanvasPane`，避免两套逻辑漂移）。

> 这样"左侧页面"与"右侧页签"共用**同一份**画布渲染与同一份视图状态，行为天然一致（也满足"保持原有功能不变"）。

### 4.3 装配（`src/client/index.ts`）

```ts
// 服务可能比我们晚激活 → 取不到就重试（既有 retrySessionsFace / retryNavigation 同款理由）
const rightTabs = readRightSidebarTabs()
installRightSidebar({ tabs: rightTabs, right: readRightSidebar() }, BranchCanvasPane)
if (rightTabs === undefined) retryRightSidebar(...)
```

### 4.4 不碰的东西（护栏）

- 不改 `sidebar.panellist` 行、不改 `main` 页的注册（现有 F-1/F-2/F-6 断言必须原样通过）；
- 不改 host 半（`/branch/*` 一个都不动）——右侧页签只用**已有的** `adopt`/`set-collapsed`/`open-file` 等；
- 不动树文档、不写会话日志；
- 不新增 npm 依赖、不改官方包。

## 6. 影响面与风险

| 风险 | 可能性 | 影响 | 处理 |
| --- | --- | --- | --- |
| `sidebarRightTabs` / `sidebarRight` 服务名与我们探测的不一致（公开 npm 线没有类型） | 中 | 右侧功能装不上 | 已按官方产物原文取证（§1.2/§1.3）；再加**形状探测 + 重试 + 可读诊断**，装不上只降级、不崩 |
| 未在 `dsh.client.inject` 里声明 → 访问服务抛错 | **高（必然）** | 入口 `apply()` 直接失败 | 里程碑里明确要补 `@deepseek-ai/dsh-client-ui-sidebar-right`；本仓库已有一模一样的教训（bug #6） |
| 右侧页签按会话存 → 无会话时 `openTab` 失败 | 中 | 点按钮没反应 | 先判断有无当前会话；没有就禁用按钮并说明（不静默失败） |
| 与官方争夺 `Ctrl+Shift+B` | 低（我们**不绑键**） | 破坏官方布局 | 明确不绑键：键位属于官方 `sidebar.right.toggle` |
| 左右两套渲染漂移 | 中 | 行为不一致 | §4.2 要求**共用** `BranchCanvas` 与同一份视图状态，不复制粘贴 |
| 右侧栏很窄（约 320~420px）时画布体验差 | 中 | 可用性 | 画布本来就是"框固定尺寸 + 双向滚动/缩放"，窄了只是滚动；必要时右侧默认**自动适配缩放**（复用既有 `canAutoFit` 语义） |

**回滚**：本功能是**纯增量**（一个新页签类型 + 一个按钮 + 一行 inject）。出问题时回滚只需
去掉 inject 与两处装配，左侧功能不受任何影响。
