## 1. 这是什么

DeepSeek Harness（目标 **0.2.0-rc.2**）的纯本地插件（包名 `dsh-branch-conversation`，无遥测、无外部网络）：
在官方侧边栏里加一个**「分支对话」可切换页**，用**节点框 + 连线的流程图**（Visio 式）管理「主对话节点 → 子对话 / 文件节点」。

- **节点** = 一次提问 + 一次回答（= 该会话的一个 turn）。
- **子对话** = 在某节点上提新问题而**新建的会话**：**不继承对话上下文**，只继承模型/人设/权限。
- **文件节点** = 只记原路径，点击交给**系统默认程序**打开。
- **主对话内容永不被改写**：插件不写会话日志、不改会话头。

### 1.1 硬需求：必须是**图形化界面**，且**能从对话的侧边栏打开**（2026-10-15 管理员再次明确）

这是本插件**不可退让的形态要求**，也是验收的第一条。
**2026-10-15 管理员把"图形化"的口径进一步钉死**：原话是
**「图形化界面需要显示可视化的流程图节点联系，类似 visio 渲染的流程图」**——
即**框 + 连线**的关系图（回到裁决 **B10** 对"轴线"的本义：多次问答节点**连成的线**）。

| 要求 | 含义 | 落地方式 | 当前状态 |
| --- | --- | --- | --- |
| **图形化 = 节点框 + 连线（Visio 式）** | ① 每个节点是**有边框的矩形框**（轮次号/标题/状态点/折叠把手/「＋」）；② 框之间**有画出来的连线**（SVG 层），端点贴框边缘，同一会话相邻轮次的**轴线也看得见**；③ 位置是**二维坐标**（同级节点成行），不是单列堆叠；④ 折叠后后代与连线消失、**剩余节点重排** | **已做（M6）**：`tree-layout.ts` 输出二维矩形 + 边，`panel.tsx` 绝对定位节点框 + 一层 SVG 连线 + 双向滚动/缩放，`panel.css` 画布样式。设计口径见[设计文档 §3.2](分支对话插件·设计文档.md)、验收口径见[完善计划 §5.5.1](分支对话插件·完善计划.md) | ✅ **已实现并实测**（冒烟 82/82；`layout-check` 真实浏览器 **88/88**；两态 10 张截图目视确认：圆角节点框 + 蓝色实线主轴 + 橙色虚线分支，无轨道字符） |

## 2. 关键决定（都已落定，别再改）

| 决定 | 依据 |
| --- | --- |
| 建子会话**不用 `fork`** | `sessionController.fork()` 会**复制事件前缀**（=继承上下文），与要求相反 |
| 建子会话用 `ctx.sessions.create(id?, { meta: { cwd, parentSession, agentPreset } })` 且**不给 seed** | 此时 `seedLength = 0`、血缘非空，语义自洽 |
| 孤儿判定靠**自己查 `list()` 现存集合** | 会话日志是 append-only，父会话被删**不会**清掉子会话头的 `parentSession` |
| 父会话被删 → **整棵子树作为一棵新独立树升为根**（裁决第 2 条 (a)） | 原节点标 `orphan`、子节点摘除、文件引用清空，树形不改写 |
| **每棵树一把锁**（锁键 `treeId`） | 同树串行、异树并行；升根按 treeId 排序取锁避免死锁 |
| **子智能体（`origin==='subagent'`）不入树** | 裁决第 7 条 |
| 导出只做 **JSON + Markdown + Mermaid** | 裁决第 4 条（DOT 不做） |
| 页面落点 = `sidebar.panellist` 行 + `main` keyed 页（同一个 id 配对） | M0 取证（已装插件源码） |
| `inject` 必须写在 **patch 行**上 | loader 读 `entry.options.inject`，不是模块导出的 `inject` |
| webserver handler 是 **Node `(req, res)`** 签名 | 真机实测，需 `dispatch()` 适配层 |
| 布局**向右生长**（根左子右）、节点**固定 208×62**、连线走**正交折线** | M6 定案：中央列"宽小于高"，向右生长只加高度且可纵向滚；固定框才谈得上"重叠判定"（设计文档 §3.2） |

## 4. 阻塞点：已解决（2026-10-15 真机轮次二）

**原阻塞**：插件前缀路由在真机上不可达（`register()` 成功但 `GET /branch/* → 404`）。
**根因（插件自身缺陷，不是组合层）**：前缀注册成 `'branch'`，而 webserver 的 `match()` 是
`pathname !== prefix && !pathname.startsWith(prefix + '/')`——**必须带前导斜杠**，
于是前缀表里留下一个永远匹配不上的键，请求落到 SPA fallback。修法：`BRANCH_ROUTE_PREFIX = '/branch'`。
对照实验：注册 `'nolead'` → `match()` 为 undefined；注册 `'/lead'` → 命中。

**修完后真机又暴露的问题（全部已修）**：见 [现状总结](分支对话插件·现状总结.md) §4 与测试文档 §6.5.4
（未 inject 的服务访问会抛错、存储根未预建、typert Remote 方法丢 `this`、create 丢历史轮次、
外壳 id 用错成面板 id、`sessions`/`uiWorkspace` 两个服务晚到的时序问题）。

**真机现状**：面板已在浏览器里跑起来——侧边栏有「分支对话」行，打开会话即自动折出轮次节点树，
切换会话会自动接入对应的树。**待人工核对的交互**：点节点切换、折叠、文件节点、导出、孤儿升根。

## 4.3 M6 画布化轮（本轮）

**改了什么**（形态从"缩进列表"整体换成"框 + 连线"）：

| 位置 | 变化 |
| --- | --- |
| `src/client/tree-layout.ts` | 输出从 `rows[]`（含轨道字符前缀）换成 `nodes[]`（`{x,y,width,height}` 矩形）+ `edges[]`（`{from,to,axis,path,x1,y1,x2,y2}`）+ `size`。布局=经典紧凑树：叶子按序占槽位、父节点居中于首末子节点；`x = PADDING + depth×(NODE_W+LEVEL_GAP)` |
| `src/client/panel.tsx` | 画布化：视口（双向滚动）→ 画布（`scale()`）→ SVG 连线层（`pointer-events:none`）+ 绝对定位节点框；折叠把手/轮次号/状态点/「＋」都在框内；新增缩放按钮与 `Ctrl+滚轮`，首次进画布按容器宽自动缩放（下限 30%） |
| `src/client/panel.css` | 旧的 `.dsh-branch-tree-*`（行/轨道/徽标）删除，换成 `.dsh-branch-canvas/-surface/-wires/-wire-main/-wire-branch/-node*`；主轴实线、分支虚线；容器查询下"徽标让位、画布收紧"，**框与线永不退化** |
| `tools/build/panel-preview.mjs` | 夹具从"渲染行"改成"渲染整块画布"（同一套类名与 `data-dsh-branch-*`），并**参数化出折叠态夹具**，用于 F-4 的前后对照 |
| `tools/smoke/tree-layout.mjs` | 断言从"轨道/缩进"换成"坐标/边/端点/不重叠/折叠重排" |
| `tools/smoke/layout-check.mjs` | 新增"节点框存在且有边框""连线条数 = 边数""框不重叠""端点贴框""框不越出画布""画布内没有 `│├└─` 残留"等断言；折叠态夹具单独量测 |

**丢掉的旧机制（有意）**：`MAX_RAILS` 轨道压缩、`.dsh-branch-tree-*` 行样式与
"每行必须有轨道字符"的断言。深树不再靠截断轨道，而是靠**画布双向滚动 + 缩放**（这正是 F-5 的新口径）。

**新增的回归防线**：断言 `railChars === 0`——画布里一旦再出现 `│├└─` 轨道字符，
说明有人把形态退回成列表了，量测会立刻红。

> ⚠️ **本轮踩到并修掉的两个"环境/工具"坑（都是真金白银的教训）**：
> ① **无头 Chromium 一度完全起不来**（`msedge --version` 无输出；`--headless=new --screenshot=<png>` 进程 `exit 0`
> 却**不落盘**；stderr 只有 crashpad `OpenProcess: 拒绝访问 (0x5)`；带 `stdio:'pipe'` 直接 `spawn EPERM`）——
> 父子代理各自复现。**后来同一台机器上又能跑了**（`--screenshot` 始终不行，但"页面 POST 回本机服务"
> 与 **CDP** 两条通道可用）。结论：这类"浏览器静默不渲染"要**如实报环境受限**，别静默当失败或当通过。
> ② **截图不能再用 `--screenshot=<png>`**：该开关在本机**永远不落盘**。改用
> **DevTools 协议**（`--remote-debugging-port` + `/json/version` 拿 WebSocket + `Page.captureScreenshot`），
> 实测能出图。另一个更阴的坑：把截图挪到 `server.close()` 之后跑，10 张图全是 Edge 的
> `ERR_CONNECTION_REFUSED` 错误页——**文件非空、断言也没红**，只有人眼看图才发现。所以截图必须写在
> 夹具服务还活着的 `try` 里，且**截图后一定要人眼过一遍**。

> ⚠️ **已知取舍（写在这里免得后面当成 bug 报）**：布局是**向右生长**的，
> 所以"同一会话连续 N 轮"会形成一条向右的**长链**（N 越大画布越宽，例如 30 轮 ≈ 8000px）。
> 这是设计文档 §3.2 定下的方向（"中央列宽小于高，向右生长只加高度"适用于**分支**，
> 而**主轴**是链式的——两者叠加时长链就是宽）。当前处置：画布双向滚动 + 首次自动缩放到适配宽度（下限 30%），
> 用户可拖滚动条或缩放。**若管理员觉得主轴过长难用**，备选方案（未做，需裁决）：
> 主轴改为纵向堆叠、分支才向右生长（"紧凑树 + 轴向脊柱"混合布局）。

- 仓库根即插件包根；四份 md 在 `docs/`，管理员的裁决原件 `问题解决回复.md` 留在根目录。
- 源码风格：中文文档注释、`.ts` 扩展名导入（`allowImportingTsExtensions`）、每处可选服务都做**形状探测**（缺失即降级 + 可读诊断）。
- 客户端形态改动要同步四处：`src/client/tree-layout.ts`、`panel.tsx`、`panel.css`、`tools/build/panel-preview.mjs`
  （夹具与页面同构，页面结构变了夹具不改，量测就会因缺元素而失败——这是**有意**的，防止静默失配）。
- 提交粒度：一个里程碑一次提交；提交信息写清"为什么"（尤其反直觉的决定）。
- git 提交用户：`fjccc-mark`。
