## 1. 这是什么

DeepSeek Harness（目标 **0.2.0-rc.2**）的纯本地插件（包名 `dsh-branch-conversation`，无遥测、无外部网络）：
在官方侧边栏里加一个**「分支对话」可切换页**，用**节点框 + 连线的流程图**（Visio 式）管理「主对话节点 → 子对话 / 文件节点」。

- **节点** = 一次提问 + 一次回答（= 该会话的一个 turn）。
- **子对话** = 在某节点上提新问题而**新建的会话**：**不继承对话上下文**，只继承模型/人设/权限。
- **文件节点** = 只记原路径，点击交给**系统默认程序**打开。
- **主对话内容永不被改写**：插件不写会话日志、不改会话头。

## 2. 关键决定（都已落定，别再改）

| 决定 | 依据 |
| --- | --- |
| 建子会话**不用 `fork`** | `sessionController.fork()` 会**复制事件前缀**（=继承上下文），与要求相反 |
| 建子会话**不走 `ctx.sessions.create`**，走 `ctx.agents.create({ sessionId, meta: { cwd, parentSession, isSeeded:false, delegationDepth:0, agentPreset }, agentOptions, setup })` 且**不给 seed** | 官方对 `sessions` 服务的原文：**"a session published outside that lifecycle persists nothing"**——`sessions.create` 建出的会话只是内存记录（id 是 `session-<n>` 计数器号），不落盘、不进会话列表，树上节点永远匹配不到真实会话。`agents.create` 才跑完整生命周期（持久化写入器就在这条链上），血缘/人设照样能写（缺陷 27，见 §4.6） |
| 孤儿判定靠**自己查 `list()` 现存集合** | 会话日志是 append-only，父会话被删**不会**清掉子会话头的 `parentSession` |
| 父会话被删 → **整棵子树作为一棵新独立树升为根**（裁决第 2 条 (a)） | 原节点标 `orphan`、子节点摘除、文件引用清空，树形不改写 |
| **每棵树一把锁**（锁键 `treeId`） | 同树串行、异树并行；升根按 treeId 排序取锁避免死锁 |
| **子智能体（`origin==='subagent'`）不入树** | 裁决第 7 条 |
| 导出只做 **JSON + Markdown + Mermaid** | 裁决第 4 条（DOT 不做） |
| 页面落点 = `sidebar.panellist` 行 + `main` keyed 页（同一个 id 配对） | M0 取证（已装插件源码） |
| `inject` 必须写在 **patch 行**上 | loader 读 `entry.options.inject`，不是模块导出的 `inject` |
| webserver handler 是 **Node `(req, res)`** 签名 | 真机实测，需 `dispatch()` 适配层 |
| 布局 | **主轴向下、分支向右**：主轴（同会话相邻轮次）同列向下叠，分支（跨会话）向右每层一列；节点**固定 208×62** | M6 + 主轴补做定案：主轴纵向让 12 轮仍只占**一列宽**（旧版向右会撑到 3000px+）；分支向右是因为中央列"宽小于高"，往右只加高度；固定框才谈得上"重叠判定"（设计文档 §3.2/§6.7.6） |
| 视图状态（缩放/滚动）记在**模块级**而不是 `useState` | F-6 实测：官方 shell 切面板会**卸载**本页，`useState` 活不过去；官方布局 store 也是瞬态（README 明说会忘）。滚动位置还必须**等树排出来再贴**（挂载那一刻 `scrollHeight` 是 0，贴了会被夹成 0） |

## 4. 阻塞点：已解决（2026-10-15 真机轮次二）

**原阻塞**：插件前缀路由在真机上不可达（`register()` 成功但 `GET /branch/* → 404`）。
**根因（插件自身缺陷，不是组合层）**：前缀注册成 `'branch'`，而 webserver 的 `match()` 是
`pathname !== prefix && !pathname.startsWith(prefix + '/')`——**必须带前导斜杠**，
于是前缀表里留下一个永远匹配不上的键，请求落到 SPA fallback。修法：`BRANCH_ROUTE_PREFIX = '/branch'`。
对照实验：注册 `'nolead'` → `match()` 为 undefined；注册 `'/lead'` → 命中。

**修完后真机又暴露的问题（全部已修）**：见 [现状总结](分支对话插件·现状总结.md) §4 与测试文档 §6.5.4
（未 inject 的服务访问会抛错、存储根未预建、typert Remote 方法丢 `this`、create 丢历史轮次、
外壳 id 用错成面板 id、`sessions`/`uiWorkspace` 两个服务晚到的时序问题）。

**真机现状**：面板已在浏览器里跑起来——侧边栏有「分支对话」行，打开会话即自动折出轮次节点树，
切换会话会自动接入对应的树。**待人工核对的交互**：点节点切换、折叠、文件节点、导出、孤儿升根。

## 4.4 主轴渲染（本轮补做）：显示层把同一会话的相邻轮次串起来

**起因**：真机复核时点开一个有 3 轮问答的真实会话，画布上是 **3 个框、0 条线**。
查树文档才看清：**同一会话的多次问答是平铺的兄弟节点**（`children` 全空），
只有"开子对话 / 挂文件"才产生父子关系——**B10 的"轴线"因此没有数据来源**。

**做法**（`src/client/tree-layout.ts`，纯函数层，**只影响观感**）。这一轮顺带把坐标系整体改成
「**主轴向下、分支向右**」——因为这正是"轴线"该有的样子，而且能顺手解掉"主轴向右撑宽画布"的隐患：

| 项 | 决定 |
| --- | --- |
| **主轴向下** | 同一会话的相邻轮次**同列**、`y` 每轮 + `NODE_H + ROW_GAP`（12 轮画布仍只占**一列宽** = 框宽 + 两侧内边距） |
| **分支向右** | 跨会话的子对话 / 文件节点从父框**右侧**起算，每深一层 `+ NODE_W + LEVEL_GAP` |
| **同一父节点的多个分支** | 都从**同一列**起算、彼此**上下叠**（不互相往右推；间距 `ROW_GAP`） |
| **分支块在父框下方** | 分支子树的整体纵向区间排在 `父框下缘 + ROW_GAP` 之后，父框不会压到自己的分支 |
| 串接判据 | 同一个会话 + 轮次**严格连续**（`n → n+1`）：兄弟之间串、**一起成为根**的之间也串 |
| 为什么是"严格连续" | 缺号（第 2 轮没进树）时 1 与 3 **不硬接**——否则"轴上每段都是相邻问答"就不成立 |
| **主轴优先于分支** | 主轴下游必须走"向下"那条路：它常常**同时**也是 `children` 里的真孩子，若按普通分支往右排，就会出现"主轴横着摆、边还用分支折线、端点对不上"（实测就是这么暴露的） |
| 真父子优先（本节点） | 若父子本来就是真关系且**父就是当前节点**，保持真层级、不标合成 |
| 折叠语义 | 折叠主轴上某一轮 → **下游整条链一起消失**（它是这一轮的延续），并计入"已折叠 N 个节点"；展开即回来 |
| 走线 | 主轴两端同列：竖线走**两框之间的空隙**（父下缘中点 → 子上缘中点），不穿框；分支：父右缘中点 → 竖线（按第几个子错开车道）→ 子左缘中点 |
| 多根 | 同一文档里互不相连的根各自成块、自上而下叠放（不重叠） |
| 数据不动 | 合成边带 `synthetic: true`；**不写树文档、不影响导出、不改折叠状态**（树的真值仍以文档为准） |

**验证**：`tree-layout.mjs` **20/20**（含 5 条主轴语义用例）；`npm run smoke` **87/87**；
`npm run layout-shots` **88/88** + 10 张两态截图（展开 19 框 / 18 线；折叠 `n6` 17 框 / 16 线）。

## 4.6 缺陷 27：建子会话的通道错了（2026-10-17，P0-A 人工交互轮）

**现象（管理者在真机上点出来的）**：在节点上「＋」建子会话 → 成功；但

1. 子会话**挂不到父会话上**（"节点成功显示，但创建的子节点没有成功挂载"）；
2. 打开子会话后，它在画布上**被当成了一棵新根**（不是父会话那棵树的一员）。

**根因（实时 inspection 拿到的官方原文，不是猜的）**：`sessions` 服务的描述写着
**"Persistence is intentionally not implemented here — the agent lifecycle attaches a session-log
writer to each published session's write handle; _a session published outside that lifecycle persists
nothing_"**。而 `sessions.create()` 不给 id 时铸的是 **`session-<n>` 计数器号**（`SessionStore.prepare`）。
我们的 `createChildSession` 正是走的这条路，于是：

- 子会话只是一条**内存记录**，不落盘、不进 `sessionController.list()`、重启即消失；
- 树上那个节点的 `sessionId` 是个**永远不存在的会话**（真机存储里真看到 `sessionId: "session-1"`）；
- 打开真实的子会话时 `resolveTreeId()` 找不到它 → `adopt` 建了**一棵新树**（= "被当成新根"）；
- 另外还有一个**独立的挂载缺陷**：挂载点取的是 `nodeOfSession()`（该会话的**第一个** qa 节点），
  所以在第 2 轮上建的分支会挂到第 1 轮下面——看起来同样像"没挂上"。

**修法**：

| 位置 | 变化 |
| --- | --- |
| `src/host/session-model.ts` | 新增 `AgentFactoryFace`（`ctx.agents`）；`createChildSession` 改走 `ctx.agents.create({ sessionId: session-<uuid>, meta: { cwd, parentSession, isSeeded:false, delegationDepth:0, agentPreset }, agentOptions, setup: presets.mount })`——与官方 `sessionController.create` 同款装配；**删掉** `store` 面 |
| `src/host/branch-service.ts` | 缺 Agent 工厂 → `unsupported`（不再退回不落盘的通道）；新增 `anchorNodeFor()` 按 `parentTurn` 选挂载点；`syncTurns()` 让**占位节点认领第一个轮次**（否则子会话跑完第一轮会多长出一个框）；`adoptSession` 改**以 inspect 为准**（刚建、还没落盘也能 adopt） |
| `src/core/types.ts` / `routes.ts` / `index.ts` / `client/capability.ts` / `panel.tsx` | 诊断字段 `sessions` → **`agents`**（自检区文案同步） |
| `src/testing/fake-sessions.ts` | 假面按实时契约重建：`agents.create` 造**会落盘**的会话；`store.create` 故意不落盘（把缺陷钉进假环境） |
| `tools/smoke/branch-m1-cases.mjs` | 新增 3 条回归：子会话 id 是 `session-<uuid>`、**在会话列表里**、`adopt` 与父会话**同一棵树**、占位节点被认领、分支挂在**点的那一轮**下 |

**真机证据（隔离 profile，不污染现有数据）**：

- `POST /branch/create {parentTurn: 2}` → `sessionId=session-ef936c1d-…`（uuid）、`treeId` = 父会话那棵；
- 子会话**立刻**在 `$DSH_HOME/sessions/…` 落盘，头里 `parentSession` / `isSeeded:false` / `cwd` / `agentPreset` 全部正确；
- `POST /branch/adopt {sessionId: 子}` → **同一棵树**、`currentNodeId` = 新节点；
- `POST /branch/view {sessionId: 父}` → `第 2 轮` 节点的 `children` 里有这个新节点（**不是**第 1 轮）；
- 真机 UI 探针（无头 Edge + CDP，点「＋」→ 填首句 → 提交）：框数 3→4、新连线 `n-2-…->n-5-…`、
  树 id 未变、新框标题=首句、无报错、地址未变；带提问的子会话日志 11.9KB（真的跑了一轮），不带提问的 372B（只有头）。

## 4.7 缺陷 28：点节点只切到对话末尾（2026-10-17，P0-A 第二轮）

**现象**：点"第 N 轮"的框 → 会话切过去了，但停在**最新一条**，跳不到对应轮次。

**根因**：只调了 `ctx.uiWorkspace.openSession(sessionId)`。官方这个接口的语义是"选择会话并显示它的
Conversation"，**没有**轮次参数（`SessionTarget = SessionId | SubagentAddress`），打开就停在末尾。

**修法**（新增 `src/client/jump-to-turn.ts`）：用**对话自己的 DOM 锚点**定位，不碰官方私有接口。

| 事实（真机 DOM 侦察到的） | 用法 |
| --- | --- |
| 滚动容器 `[data-conversation-scroll]`；每轮消息带 `data-chat-turn="<n>"`，用户那条另有 `data-chat-flow-kind="user"` | 挑该轮**用户提问**那条 → `scrollIntoView({block:'start'})` |
| 对话**分页加载**：很早的轮次一开始不在 DOM 里 | 节点上的 `anchorSeq` → 官方 `ISession.loadThrough(seq)`（经 `ctx.sessions.using()` 借引用、跑完释放）→ 再等锚点 |
| 刚切会话时 transcript 还没渲染 | 轮询等锚点（默认 3s）；找不到就**保持原行为**（停末尾），不抛、不弹错 |
| 要让人知道"就是这一轮" | 命中元素打 `data-dsh-branch-flash`（1.4s 后撤）+ 一条 token 化 outline；它同时是真机门的断言抓手 |

`scrollTop=47`；`npm run real-machine` **F-15 四条断言全绿**（定位到被点的轮次 / 该轮在视野内 /
跳完已切回对话 / 滚动位置离开末尾）。

- 源码风格：中文文档注释、`.ts` 扩展名导入（`allowImportingTsExtensions`）、每处可选服务都做**形状探测**（缺失即降级 + 可读诊断）。
- 客户端形态改动要同步四处：`src/client/tree-layout.ts`、`panel.tsx`、`panel.css`、`tools/build/panel-preview.mjs`
  （夹具与页面同构，页面结构变了夹具不改，量测就会因缺元素而失败——这是**有意**的，防止静默失配）。
- **改过客户端产物后，真机复核前必须重启 profile**：`link:` 安装指向工作区，但服务启动时就把产物读进内存了
  （本轮实测：不重启的话 `/plugins/...` 还是旧字节；重启后 `served-bundle` 才为绿）。
- **形态门 `F-*` 现在都是自动量测**：`served-bundle`/`real-machine`（真机）+ `layout-check`（夹具几何）。
  新增形态行为时请同时补这三处之一，别再只写"人工核对"。
- 提交粒度：一个里程碑一次提交；提交信息写清"为什么"（尤其反直觉的决定）。
- git 提交用户：`fjccc-mark`。
