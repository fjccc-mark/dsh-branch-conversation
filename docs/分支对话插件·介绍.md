## 1. 一句话

**`dsh-branch-conversation` 是 DeepSeek Harness（DSH）的一个纯本地插件**：在对话界面里加一个
「分支对话」页，用**类似 Visio 的流程图**（节点框 + 连线）管理"主对话的每一次问答 → 由此岔出的子对话 / 挂上的文件"。

- 包名 `dsh-branch-conversation`，显示名「分支对话」，目标内核 **DSH ≥ 0.2.0-rc.2**。
- 不联网、无遥测；树数据存在本机 `$DSH_HOME/storages/branch-conversation/v1/`。
- **不改写主对话**：不写会话日志、不改会话头，树只是挂在会话之上的一层结构。

---

## 2. 它解决什么问题

DSH 的会话列表是**线性的**：一个会话从头聊到尾，新话题要么在同一会话里继续（上下文越滚越长），
要么开一个全新会话（上下文清空，但**和原来的讨论彻底断了联系**）。

真实的思考过程更像树：某一段问答里冒出一个值得单独展开的问题，你想**从那个点岔出去**，
又希望在回头时**看得见它是从哪一段长出来的**。插件把这件事补上：

| 你会遇到的场景 | 插件给的答案 |
| --- | --- |
| 第 3 轮讨论到一半，想**带着前面的上下文**换个方向继续，又不想把新内容塞回主对话 | 在「第 3 轮」节点上「＋」→「**原生分支**」：走 DSH 官方 fork，**继承这一轮及之前的上下文**，并**进入父对话的工作区**（和聊天里的「在新对话中分支」同一条通道） |
| 第 3 轮的回答里提到一个概念，想就它单独深聊，但**不想污染主对话上下文** | 在「第 3 轮」节点上「＋」→「建子会话」：新会话、**不继承上下文**、只继承人设/模型/权限，血缘挂在第 3 轮下 |
| 聊到某个文件（设计稿、日志、脚本），想随时点开 | 在节点上「＋ → 挂文件」：只记**原路径**，点一下用系统默认程序打开 |
| 会话越开越多，忘了某个子对话是从哪来的 | 画布上**连线**就是来源：橙虚线从父框指向子框，点节点直接跳回那一轮 |
| 想把这棵树交给别人 / 存档 | 一键导出 **JSON / Markdown / Mermaid**（Mermaid 可直接渲染成图） |
| 父会话被删了，子对话还留着 | 孤儿检测：整棵子树**升为独立的树**，原位置留 `orphan` 标记，不丢数据 |

## 3. 核心概念（五个词）

| 词 | 定义 |
| --- | --- |
| **节点** | 主对话里的**一次提问 + 一次回答**（一个 turn）。画布上是一个 `208×62` 的有边框矩形框，带轮次号、状态点、折叠把手、「＋」 |
| **原生分支** | 在某个节点上开、**继承这一轮及之前的上下文**的会话：走官方 `sessionController.fork`，子会话 `isSeeded=true`，并**自动进入父对话的工作区**。框内标「继承上文」 |
| **子对话** | 在某个节点上提新问题而**新建的会话**。**不继承对话上下文**（`seedLength = 0`），只继承父会话的 **模型 / 人设 / 权限**（同一个 `agentPreset` 与 `cwd`） |
| **文件节点** | 只记**原路径**的文件引用：不复制、不托管、不读内容；点击交给系统默认程序。相当于"只有一次引用的叶子" |
| **主轴 / 分支** | **主轴** = 同一会话里相邻轮次连成的线（实线，纵向）；**分支** = 跨会话的原生分支 / 子对话 / 文件节点（虚线，向右） |

另外两条规则：

- **子智能体不入树**：模型自己派发的 subagent 不算节点（那属于它的内部工作）。
- **树是显示层 + 结构层**：轮次主轴是渲染时合成的（`synthetic: true`），不写进树文档、不影响导出与折叠状态。

## 4. 怎么用

### 4.1 安装

| 环境 | 装法 |
| --- | --- |
| 网页端（自建 profile，如 `web`） | `dsh plugin --profile web add link:<本仓库绝对路径>`，命令会建好 profile；装完**重启该 profile** 才读到宿主半 |
| **桌面端**（Electron 独占 `desktop` profile） | 只能在**应用内插件管理器**（设置 → 插件）里装 `link:<本仓库绝对路径>`。CLI 会报 `profile "desktop" is managed exclusively by the Electron application`。装完**热应用、不用重启** |

> 需要从零自测时，用 `dsh plugin --profile branch-dev add link:<仓库>` 建一个临时 profile，
> 再 `dsh --profile branch-dev --dump-config` 确认插件层已出现。

### 4.2 打开

在官方侧边栏点「**分支对话**」那一行，中央列就切换成画布页（与"对话 / 轨迹 / 文件"同栏共存、可来回切）。
它**不是独立窗口、不是独立网址、不需要开终端**。

### 4.3 常用操作

| 想做什么 | 怎么做 |
| --- | --- |
| 看某个会话的树 | 先打开那个会话，再点「分支对话」；页面顶部显示**当前会话**与**所在树** |
| 从某轮**带着上文**岔出去 | 点该轮框右上角「＋」→「原生分支」（默认页签）→ 首句提问可留空 → 建原生分支。新会话继承这一轮及之前的上下文，并进入父对话的工作区 |
| 从某轮**开一条全新**的子对话 | 点「＋」→「建子会话」→ 首句提问可留空 → 建子会话（不继承上下文） |
| 挂一个文件 | 点「＋」→ 切到「挂文件」页签 → 填**绝对路径** → 挂文件（路径不存在会标「文件不存在」） |
| 跳回某一轮 | 点那个框：切到对应会话**并滚到那一轮**（很早的轮次会先把历史加载到那一轮） |
| 折叠一棵子树 | 框内「▾/▸」；折叠后**后代与连线一起消失、剩余节点重排**，状态写进树文档（刷新仍在） |
| 平移 / 缩放画布 | 滚动条 / 触控板平移；工具条「−/+」或 `Ctrl+滚轮` 缩放（30%~200%，首次进页面自动适配宽度） |
| 导出 | 工具条「导出 JSON / Markdown / Mermaid」，落成文件下载 |
| 在右侧详情列看 | 工具条「在右侧打开」（网页端 `Ctrl+Shift+B`、桌面端 `Ctrl+Alt+B` 那一栏）；它会先切回对话再开页签 |
| 处理孤儿 | 树上有孤儿时出现「处理孤儿（拆分升根）」按钮 |
| 自检 | 页面底部「运行环境自检」：`ctx.agents` / `sessionController` / `nativeFork` / `agentPresets` / 存储根可写 / 现有树数量 |

## 5. 边界与约束（有意为之）

| 项 | 说明 |
| --- | --- |
| **不改主对话** | 插件不写会话日志、不改会话头、不删会话（会话归档留给别的插件） |
| **子对话不继承上下文** | 这是"子对话"这个动作的需求（裁决 B3）；它走 `agents.create`、不给 seed。**原生分支**是另一个动作，走官方 `fork` 并继承上下文——两者并存，不要互相替代 |
| **原生分支必须继承上下文与工作区** | 这是 DSH 官方 fork 的语义（2026-10-18 需求）：复制截止被点轮 `turn/end` 的前缀，并由官方 `forkWorkspace()` 把子会话挂进父会话的工作区；插件不自己复制事件、不自己改会话头 |
| **v1 的写动作** | 只有：建子会话、挂文件、折叠、父会话被删后的拆树升根。**不提供**重命名 / 移动 / 删除节点 |
| **文件只记路径** | 不复制、不托管、不读内容；文件被移走时用体检把 `missing` 回写到树文档 |
| **纯本地** | 无遥测、无外部网络请求；路由只绑 `127.0.0.1`（`/branch/*` 目前**未鉴权**，属待裁决项） |
| **并发** | **每棵树一把锁**（异树并行），文档写入走"临时文件 + fsync + rename"原子发布 |
| **降级** | 依赖的官方服务缺失时**关功能 + 打印可读诊断**，页面照常可用；树文档损坏 / 高版本 schema → 只读降级，不覆盖坏文件 |
| **子智能体** | `origin === 'subagent'` 的会话整条排除，不入树 |

## 6. 它是怎么工作的（30 秒版）

```text
浏览器半（侧边栏行 + 中央列画布）        host 半（Node 进程）
  panel.tsx / tree-layout.ts               index.ts → /branch/* 路由
  纯函数算坐标 + SVG 连线                    ├─ branch-service.ts  建分支 / 补节点 / 折叠 / 升根 / 开文件
  点框 → 切会话 + 滚到那一轮                  ├─ tree-store.ts      每树一把锁 + 原子写 + 只读降级
        │                                    ├─ session-model.ts   只读会话：inspect 折轮次 / 建子会话 / 投递首句
        └────────── fetch /branch/* ────────→└─ core/export.ts      JSON / Markdown / Mermaid 纯函数
                                                   │
                                    树文档 <DSH_HOME>/storages/branch-conversation/v1/*.json
```

几个关键取舍（都有取证依据，详见 [README「关键设计决定」](../README.md)）：

- **建子会话走 `ctx.agents.create` 且不给 seed**：只有 Agent 生命周期的链路才会给会话挂持久化写入器；
  `ctx.sessions.create` 建出来的会话**不落盘**（官方原话：*"a session published outside that lifecycle persists nothing"*）。
- **样式随产物发布**：加载器只取模块导出、不执行 CSS 副作用，所以 `panel.css` 被打包成 `window.__DSH_BRANCH_CSS__`，
  由 `apply()` 运行时插成 `<style>`。
- **孤儿靠自己查**：会话日志是 append-only，父会话被删不会清掉子会话头里的血缘字段，所以"父还在不在"以会话列表为准。
- **只画排布期真正建立的边**：折叠/损坏数据（环、自环）下若事后拿 `children` 重算，会多画边。

## 8. 术语与常见问题

**Q：子对话为什么"看不到上文"？** 这是"建子会话"这个动作的设计：只继承模型/人设/权限，不继承对话历史（`seedLength = 0`）。
如果你要"**带着上文**岔出去"，用同一个「＋」里的「**原生分支**」页签——它走官方 fork，继承这一轮及之前的上下文，
并进入父对话的工作区；官方聊天里的「在新对话中分支」也是同一条通道。

**Q：点了节点，会话切过去但停在最新一条？** 现在会**滚到那一轮**并短暂高亮（`data-dsh-branch-flash`）；
很早的轮次会先调官方 `ISession.loadThrough(anchorSeq)` 把历史加载到那一轮，找不到就保持"停在末尾"而不报错。

**Q：树数据存在哪？** `$DSH_HOME/storages/branch-conversation/v1/`（可在插件配置里改 `storageRoot`）：
每棵树一个 `<treeId>.json`，外加一个只用于加速的 `_index.json`（索引丢了会扫存储根重建）。

**Q：网页端和桌面端会看到不同的树吗？** 不会——两端共用同一个 `$DSH_HOME`，看到的是同一批树文档。

**Q：卸载插件会删数据吗？** 不会。卸载只移除代码与注册；树文档留在原处，重装后可继续用。

**Q：为什么侧边栏里是"一行 + 中央列一页"，而不是一个浮窗？** 这是管理员钉死的形态底线：
必须挂在官方 `sidebar.panellist` 行上、与官方行同栏共存，页面落在 `main` 中央列——**不塞进窄侧栏轨道、不做独立窗口**。
