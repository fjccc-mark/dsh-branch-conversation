## 0. 一句话设计

在 DSH **官方侧边栏**里新增一个**可切换页**（与官方文件树同栏）：主对话的每个「一次问答」是一个节点，节点下可挂子对话与文件节点；**子对话是一条全新的 DSH 会话**，只继承父会话的模型/人设/权限，不继承对话内容，靠**会话血缘元数据**挂回树上；面板只读渲染树，点击节点完成会话切换与文件预览。

## 1. 概念与数据模型

### 1.1 概念（与回复 A1/B10 对齐）

| 概念 | 定义 | 与 DSH 的对应物 |
| --- | --- | --- |
| **轴线** | 一个会话里，多次问答节点**用连线串成的线**（图上必须是**看得见的连线**，不是缩进或文字符号） | 一条 DSH 会话（Session）的事件流 |
| **节点** | **一次提问 + 一次回答**；文件节点也算节点 | 会话事件流中 `user/message` … `turn/end` 的**一个 turn**；**只计人发起的轮次** |
| **子对话** | 挂载在父对话某节点下的对话 | 一条**新会话**，血缘指向父会话（可为子对话，形成深树） |
| **文件节点** | 挂在某节点下的一个文件引用（只记原路径，供快速打开） | 工作区路径（v1 不做复制、不做托管） |
| **分支** | 在某节点的语境下提出新问题 → 开启一个子对话 | 建会话动作 + 树上的父子边 |

> 术语修正（相对于原文档）：原文档把「节点」写成「AI 的每一次回复」。按 A1/B10 定为**一次问答**，因此节点身份 = **turn 序号**，而不是单条 assistant 消息。这直接决定了锚点与 UI 的颗粒度。
>
> **排除规则（第 7 条裁决）**：模型自己派出的**子智能体**不进入这棵树。判定口径：会话头上 `origin === 'subagent'` 的会话及其后代不建节点、不显示；`turn/start` 到 `turn/end` 之间若整轮由子智能体驱动（用户消息来源为 subagent 而非人类输入），同样不计为节点。人类可发出的追问（`ctx.subagents.followup` / `reportFrom`）产生的会话若带 `origin: 'subagent'`，仍按此规则排除——**只有人点击创建的会话才成为树上的子对话**。

### 1.2 落库结构（插件自有，B2「存储独立于 DSH」）

> **存储布局已定稿（M1，2026-10-15 同步）**：实际落地为 **`<存储根>/<treeId>.json`**（每棵树一份文档）
> 加 **`<存储根>/_index.json`**（会话 → 树的加速索引）。**文件名用 `treeId` 而不是根会话 id**——
> 因为升根后根会话会变，而树的身份应当延续（§1.2 要点 6）。索引**只是加速**：缺失或指错时扫描存储根重建，
> 真相永远在树文档里。默认存储根为 `$DSH_HOME/storages/branch-conversation/v1/`（见 §2.5）；
> 下面注释里的 `branch-tree/v1/<rootSessionId>.json` 是最初设计稿的写法，**已作废**，仅保留以对照字段结构。

```jsonc
// <存储根>/<treeId>.json   （每棵树一份文档；另有 <存储根>/_index.json 作加速索引）
{
  "schema": 1,
  "treeId": "t-…",                 // 树自身 id：父会话被删后「升为根」时沿用，保证可追溯
  "originTreeId": "t-…",           // 本树从哪棵树脱离出去（无则为 null）
  "root": { "sessionId": "…", "cwd": "D:\\…", "createdAt": 0, "title": "…" },
  "nodes": [
    {
      "id": "n-…",                  // 插件自有的稳定节点 id
      "sessionId": "…",             // 该节点所属会话（主对话或某条子对话）
      "turn": 3,                    // 该节点在该会话中的 turn 序号（= 节点身份）
      "anchorSeq": 41,              // 该 turn 的 turn/end 事件 seq（建子会话时的血缘锚点，只读参考）
      "kind": "qa",                 // "qa" | "file"
      "label": "…",                 // 展示用短标题（可从提问首行派生）
      "collapsed": false,           // 叶子节点可折叠（B10:1）
      "orphan": false,              // 该节点所属会话已被删除（会话内容不可再读）
      "children": ["n-…", "n-…"],   // 子节点（多个子对话；B7:1）
      "file": null                  // kind="file" 时: { "path": "D:\\…", "missing": false }
    }
  ]
}
```

**设计要点**

1. **树文档与 DSH 会话解耦**：文档只存"关系 + 展示增强"，会话内容永远从 DSH 读。DSH 数据被外部改坏，最坏情况是丢标题/折叠状态，不会丢对话。
2. **可重建**：`nodes[].sessionId` + DSH 会话头的 `parentSession` 足以在树文档丢失时重建骨架（见 §3.5）。
3. **节点 id 与 turn 的关系**：`(sessionId, turn)` 是语义主键；`id` 是内部键，便于将来做移动/重挂（B9:2）。
4. **不写 DSH 会话日志**：v1 只读会话（`list` / `page` / `inspect`）。
5. **`orphan` 是插件自己的判定**：DSH 的会话日志是 append-only，父会话被删**不会**改写子会话头里的 `parentSession`，所以"父还在不在"必须由插件查 `list()` 得到，不能只看血缘字段（见 §2.2「删除父会话」）。
6. **`treeId` 独立于 `root.sessionId`**：因第 2 条裁决允许"整棵子树升为根"，此时根会话换了，但树的身份应当延续，便于导出与追溯。

### 1.3 与 DSH 会话的关系

```
DSH 会话头 SessionHeader { id, cwd, createdAt, parentSession?, seedLength?, agentPreset?, origin?, delegationDepth? }
        ↑ 由 DSH 拥有、持久化在 DSH 侧
插件树文档 Node { sessionId, turn, anchorSeq, children[], … }
        ↑ 由插件拥有、持久化在插件存储根
二者用 sessionId 关联；DSH 侧的 parentSession 是血缘的权威来源，插件侧是展示与锚点的来源
```

## 2. 会话管理系统设计（C3）

### 2.1 三个角色

| 角色 | 归属 | 职责 |
| --- | --- | --- |
| **DSH 会话内核** | 平台（不改） | 会话日志、轮次事件、模型调用、持久化（`session.v4.jsonl.zstd`）、父子血缘字段 |
| **本插件（分支管理器）** | 本仓库 | 树关系、锚点、文件节点、面板渲染、建分支/跳转动作、导入导出 |
| **`dsh-session-archive`（会话库）** | 已装的第三方插件 | 全库浏览、归档、批量删除、按 `parentSessionId` 的父子树（**不重叠**：它管"库"，本插件管"树"） |

### 2.2 关键动作与语义（逐条对应你的裁决）

| 动作 | 规格 | 依据 |
| --- | --- | --- |
| **建子对话** | 在节点 N（会话 S 的第 t 轮）上"提出新问题" → 建一条新会话 C：`cwd` 同 S、`agentPreset` 同 S、**无 seed**（不复制任何父会话消息）、血缘 `parentSession = S` → 在树文档中把 C 的第 1 个节点挂到 N 下 | A2、B3 |
| **上下文** | **不继承**：子会话从空上下文开始；只继承模型/人设/权限 | B3 |
| **同一节点多子** | 允许，按创建时间排序展示（B7:1） | B7 |
| **文件节点** | 记录原路径；点击调用 DSH 官方文件预览打开；文件不存在时标 `missing` 并可"清理路径"（B2:2 的"孤儿节点中文件路径删除"） | A3、B2、B5 |
| **主对话不变** | 插件不写入主对话会话日志；"不变"= **主对话的上下文不变**，树结构变化不算改变主对话 | A4 |
| **分支收束** | **不收束、不回流**；子对话只是结构上挂在父节点下（类似注释） | A5、B4 |
| **删除父会话** | 按第 2 条裁决 (a)：该节点的**整棵子树作为一棵新的独立树升为根**——树文档拆分为新文档，`root.sessionId` 换成那个子节点所属的会话，`originTreeId` 记录来历，**树形关系一律不改写**；该节点（被删会话的节点）标记 `orphan` 并保留为历史位置；该节点上的**文件引用**删除；若该节点有多个子节点，则为每个子节点各生成一棵新树 | B2:2、B7:2 |
| **孤儿判定** | 父会话被删后，子会话头里的 `parentSession` **不会**被 DSH 清掉（append-only 日志），因此必须以 `sessionController.list()` 的现存会话集合为准：节点 `sessionId` 不在集合中 → `orphan: true` | 技术事实 |
| **并发** | **每棵树一把锁**（第 5 条裁决）：不同树的写入可并行；同一棵树的写操作串行化 + 幂等。锁的作用域是 `treeId`，跨标签页由 host 侧单点持有 | B7:3 + 第 5 条 |
| **更改能力** | v1 允许：新建子对话、挂文件、折叠展开、切换、导出。不允许（仅预留接口）：重命名/移动/删除节点、拖动改挂 | B9:3 + 第 3 条 |

### 2.3 动作时序（建子对话）

```
用户：在节点 N 上点「在此节点提新问题」
 ① UI 收集输入 → 调 host 路由 branch/create
 ② host：校验 N 属于当前主对话树、S 会话存在、并发锁空闲
 ③ host：会话工厂 → 新会话 C
      · cwd        = S.cwd
      · agentPreset= S.header.agentPreset            ← 人设/能力的继承点
      · seed       = 无（不复制前缀）                 ← 上下文不继承
      · meta.parentSession = S.id                     ← 血缘（供 archive/树重建用）
 ④ host：树文档写入 C 的根节点，挂 N.children
      · 原子写（临时文件 + fsync + rename）、串行化、失败即回滚已建会话
 ⑤ 返回 C.id → UI 侧 ctx.uiWorkspace.openSession(C.id) 完成切换
```

> **技术前提（第 ③ 步）**：`ctx.sessions.create()` 的 `meta` 支持 `parentSession` / `agentPreset`，且 **seed 可缺省**（缺省即空日志）。语义上这满足了「有血缘、无继承」。`SessionController`（Remote 面）的 `create` 请求是否暴露 `parentSessionId` 参数尚需在 M0 用当前版本类型确认；若未暴露，则用 `SessionStore` 面建会话后用 Remote 面只做导航（详见 §6 兼容性）。

### 2.4 会话工厂（host 侧接口草案）

```ts
interface BranchSessionFactory {
  /** 在父会话的某个 turn 下创建一条不继承上下文的新会话。 */
  createChild(input: {
    parentSessionId: SessionId
    parentTurn: number
    /** 派生标题用：父节点提问的首行，可为空 */
    parentLabel?: string
  }): Promise<{ sessionId: SessionId }>

  /** 建文件节点（只记路径，不复制、不读内容）。 */
  attachFile(input: { ownerNodeId: string; path: string }): Promise<{ fileNodeId: string }>
}
```

### 2.5 存储与并发（B2 + B7:3 + 第 5 条裁决）

| 事项 | 规格 |
| --- | --- |
| 存储根 | 独立于 DSH 会话存储，位于 DSH 用户目录下的插件专属子目录；**已定稿（源码 `src/index.ts` 的 `defaultStorageRoot()`）：`$DSH_HOME/storages/branch-conversation/v1/`**（`DSH_HOME` 缺失时退回 `$USERPROFILE/.dsh`），配置项 `storageRoot` 可覆盖；**不使用 `process.cwd()`** |
| 写入 | 每棵树一个写队列；同目录临时文件 + fsync + 原子 rename；写失败保留旧文件 |
| 读 | 启动/刷新时全量读一次，之后按需增量；文件缺失视为空树并从血缘重建 |
| 版本 | 文档带 `schema`；不认识的高版本 → 只读降级并提示，不静默改写 |
| **并发（定案）** | **每棵树一把锁**：锁键 = `treeId`，同一棵树的写操作（建分支 / 挂文件 / 折叠 / 拆分升根）串行化并幂等；**不同树之间可并行**。锁由 host 侧单点持有，client 只发命令。升根拆分涉及两棵树 → 按固定顺序获取两把锁，避免死锁 |
| 清理 | 会话被删 → 标 `orphan` 并按第 2 条裁决拆树升根；提供一条"清理孤儿"动作（B9:3 的接口预留） |

### 2.6 权限与边界

- 只读会话日志；**不写** `session.v4.jsonl.zstd`。
- 文件节点只记路径、不读内容；点击打开交给 DSH 官方预览。
- host 路由沿用"回环 + 受信任客户端"信任边界（与 git-graph/ssh 插件同一做法），不对 LAN 未配对客户端开放。
- 无遥测、无外部网络请求（C9）。

## 3. UI 设计（B1、B5、B10）

### 3.1 落点（第 6 条裁决：成为可切换页；M0 已取证）

**M0 取证结论（有源码证据，非推测）**：官方侧边栏的「页」由**两个互相配合的座位**构成——

| 座位 | 角色 | 已装插件的实测用法 |
| --- | --- | --- |
| `sidebar.panellist`（list 槽） | 在侧边栏的**全局面板行列表**里加一行（官方 Plugins / Schedule 行也在其中，`order` 控制排序） | `slots.register({ name:'sidebar.panellist', id, order, label }, Icon)` |
| `main`（keyed 槽） | 该行的**主区页面**（中央列），只有本面板被选中时才挂载 | `slots.register({ name:'main', key: id, children, inject }, Page)` |

两者用**同一个 `id`/`key`** 配对；**官方 shell 负责行盒子、标签、选中高亮、折叠导轨、面板切换与窗口 chrome**——插件只画图标与页面内容。证据：本机已装 `dsh-client-ui-task-board` 的 `src/client/native-panel.tsx`（109–139 行）与 `dsh-ssh` 的同名文件；两者都走 `ctx.slots.inject(...)`，因此**加载顺序无关**，壳没有该座位时回调不执行（自然降级，不崩）。

**据此定案**：

- 本插件注册 `sidebar.panellist`（「分支对话」行，`order` 排在官方行之后）+ `main`（`key = 'branch-conversation'`，承载**流程图页面**）。
- 流程图放在**中央列**（宽度足够画树），**不塞进 56px 侧边栏**——第 6 条裁决的"可切换页"由这套配对机制精确实现。
- 点击节点：
  - `kind="qa"` → 会话切换：`ctx.uiWorkspace.openSession(sessionId)`（官方导航面；`WorkspaceBrowserInjected` 也提供 `open(sessionId)`）。
  - `kind="file"` → 见下方"文件打开的两种路线"。
- 叶子节点可折叠（B10:1），折叠状态持久化在树文档。
- 子对话内可再建分支时（第 8 条裁决：真实父子链），页面按"当前会话所在的那棵树"定位显示，并高亮当前节点。

**文件打开的两种路线（需你在 §3.5 二选一）**

| 路线 | 机制 | 优点 | 缺点 |
| --- | --- | --- | --- |
| ① 系统默认程序打开 | `sessionController.canOpenWorkspacePath()` + `openWorkspacePath({ path })`（官方 Host API，SDK 已确认存在） | 实现确定、零猜测、任何文件类型都行 | 跳出应用，不是"应用内预览" |
| ② 应用内预览 | 用插件自己的页面渲染文本/Markdown（`main` 页内抽屉） | 与"预览"的字面意图一致 | 需自己实现读取与渲染；图片/二进制另需方案 |

> **重要更正**：官方侧边栏里**没有"文件预览"这个现成座位**。M0 已核实 `sidebar.workspaces` 座位是**会话/工作区浏览器**（会话列表、搜索、重命名、归档、新建会话），**不是文件树**；已装插件中也没有任何"文件预览"座位被注册。因此 B5 的"调用 DSH 本身的侧边栏预览文件"**在当前版本无法字面实现**，必须按上表二选一（见 §3.5）。

### 3.2 图形化口径（**2026-10-15 管理员再次明确：必须是"看得见连线"的流程图**）

管理员原话：**「图形化界面需要显示可视化的流程图节点联系，类似 visio 渲染的流程图」**。

这条把"图形化"的口径钉死，也回到 B10 对**轴线**的原始定义（"多次问答节点**连成的线**"）：

- **节点** = 一个**带边框的框**（不是一行文字）：框里放轮次号、提问首行/短标题、文件图标、状态点、子分支计数。
- **连线** = 父子节点之间**画出来的线**（正交折线或贝塞尔曲线），端点贴在框的边缘上；同一会话的相邻轮次之间也要有线（轴线可见）。
- **布局** = 二维坐标：每个节点算出 `{x, y}` 与尺寸，**不允许用缩进/`│├└─` 字符或纯列表冒充**。
- 参考观感：**Visio / draw.io 的流程图**——框 + 连线 + 方向感，而不是文件树式的缩进列表。

**实现选型（本节定案）**

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 布局方向 | **向右生长**（根在左，子节点在右）；**备选**：自上而下分层 | 中央列通常"宽度小于高度"：向右生长只加高度（纵向滚动很自然），自上而下会让同级节点横向铺开、很快就横向溢出。窄屏下这个差别是决定性的 |
| 节点渲染 | **绝对定位的 DOM 框**（`position:absolute` + `left/top`） | 节点仍是真按钮：可点击切换会话、可 Tab 聚焦、可 `aria-*`；比 SVG/canvas 内画文字更好维护、也天然支持中文截断 |
| 连线渲染 | 一层**绝对定位的 `<svg>` 覆盖层**（`pointer-events:none`），按节点矩形边缘算端点 | 框在 DOM 层、线在 SVG 层，两层共用同一套坐标；线不拦截点击 |
| 布局算法 | 纯函数（与现有 `layoutTree` 同族）：先算尺寸，再按"叶子顺序 + 父节点居中"排 `y`，`x` 按深度累加 | 经典"紧凑树"排法；纯函数便于单测，也便于量测断言 |
| 折叠 | 折叠后**后代不进布局**，父框随之收回并重排 | 这才是"图形行为"（F-4）：线也要跟着变，不是只改文字 |
| 大图 | 画布**双向滚动** + 缩放（约 30%~200%）；视图状态（缩放/滚动）留在会话内 | 深树/多分支必然超出视口 |
| 窄屏 | 保持"框 + 线"不退化；容器内双向滚动，必要时默认缩小到适配宽度 | F-5 的新口径：退化的是**字号与显示量**，不是**图形本身** |

> ✅ **已按本条落地（M6，2026-10-16）**：`src/client/tree-layout.ts` 已把输出从"一行一个节点的轨道前缀"

> 保留下来的是 `layoutTree` 的折叠/标记/计数等**语义**部分（它们与形态无关）。

### 3.3 视觉与可达性

- 节点显示：状态点（当前/运行中/孤儿/文件缺失）、短标题、轮次号、子分支计数。
- 连线：正交或曲线，颜色/粗细区分"主轴线"与"子对话分支"，折叠时断开的后代连线不画。
- 交互：点击框切换会话、点「＋」建子会话、点折叠把手收起子树、画布可拖动平移与滚轮缩放。
- 键盘可达（Tab/Enter/Escape）：**框本身是按钮**，Tab 依次聚焦；`:focus-visible` 明显；reduced motion 下不做位移动画。
- 面板内容区内部滚动；窄屏有独立高度上限，画布双向滚动。

### 3.4 只读约束的 UI 表现（第 3 条裁决）

- v1 不提供：拖动改挂（拖动画布 ≠ 拖动节点）、删除节点、重命名节点（代码里留接口，UI 不出现）。

### 3.5 文件节点的"打开方式"——**已定案：路线 ①**

**裁决（2026-10-14，第三轮）：走系统默认程序打开。**

- 点击文件节点 → 调官方 host API `sessionController.canOpenWorkspacePath()` / `openWorkspacePath({ path })`，交给操作系统默认程序。

## 6.7 M2 验收记录（浏览器半形状 + 流程图）

### 6.7.1 浏览器半的加载协议（已打通）

用官方插件产物反推出的协议，并据此改造构建：

```js
window.__ModuleLoader__.load({
  id: "dsh-branch-conversation",   // ← 必须是**包名**（2026-10-15 修正，原先错写成面板 id）
  factory: (require) => { var module = { exports: {} }; var exports = module.exports; …; return module.exports }
})
```

> **为什么 id 是包名（真机实测 2026-10-15）**：client-modules 的 `register()` 用
> `stripClientSuffix(registration.id)` 当注册表的键（只去掉结尾的 `/client`），而 boot 图里
> 这一行的 id 由**包名**生成（`{"id":"dsh-branch-conversation","url":"plugins/??…"}`）。
> 注册成面板 id（`branch-conversation`）会让 loader 查不到该键，报
> `client-modules: could not load "dsh-branch-conversation": … loaded without registering …`，
> 表现为侧边栏出现「Failed to load plugins / 1 entry did not activate」。
> 官方插件的产物同样是包名（`id: "dshmarket"`、`id: "@deepseek-ai/dsh-client-ui-sidebar"`）。
> **注意区分**：`sidebar.panellist` 行与 `main` 页的配对键仍是面板 id `branch-conversation`。

- 构建改成**双配置**：host 半 ESM（`lib/index.js`、`lib/invariant.js`、`lib/testing/fake-sessions.js`）；
  浏览器半 **CJS**（**`lib/client.js`**；M4 前曾是 `lib/client/index.js`，因官方 client-modules 直接按 `exports["./client"]` 解析产物路径而改，见 §6.7.3 bug #1），`react` / `react/jsx-runtime` / `react-dom` / `@deepseek-ai/*`
  全部外部化——它们的 `require(...)` 由 shell 的模块表解析，**不能打进产物**（否则会出现第二份 runtime）。
- 加载器外壳由 `tools/build/wrap-client-bundle.mjs` 在构建后套上（幂等：已包装则跳过），`npm run build` 里串起来。
- `id` 必须与 `sidebar.panellist` 行 / `main` 页的配对键及 `cordis.patch.yml` 的插入名一致。

**验证**：`tools/smoke/client-bundle.mjs`（**7/7**）在最小 `window` + 模块表环境里真实加载产物，断言：
外壳形状与 id、导出形状（`apply` 是函数、`inject` 含 `slots`）、**没有请求模块表之外的模块**、
两个座位都注册且 id/key 配对一致、壳没有 `slots` 时不抛错、拿不到会话目录时 `mainViewSessionIdOf` 返回 null、

**已修的真机 bug**

| # | 现象 | 根因 | 修法 |

   - `GET /branch/diagnostics` → 404（空 body）
   - `POST /branch/diagnostics` → 405（空 body）

**已排除**：`webServer` 名称错（`register` 能调用）、实例错（port/host/前缀表都对）、路径写法错（`branch` 与 `/branch` 都试过）、
inject 未生效（子上下文有该服务）、路由被 effect 立即释放（不套 effect 也一样）、handler 抛错（探针根本没执行）、
方法限制（GET 与 POST 都试过，GET 走 404 而非 405）。

**下一步排查方向（留给下一次真机会话）**：对照官方 `client-connection` 注册 `/api` 与插件注册前缀的差异——
它是在 `apply` 里 `ctx.inject(['webServer'], webCtx => webCtx.webServer.register(...))`（与本插件同款），
但与官方 `dsh-web-app` 同一条 patch 层、同一个 `webServer` 实例；怀疑差异在
**路由表被谁在启动后重建/替换**（例如 SPA dist 的 `registerFallback` 与某个 `webServer` 代理层），
或 `dsh-host-webserver` 的实例在 web 组合里被另一份代码包装。定位手段建议：在 `match()` 入口临时加日志（需要改官方包，属临时只读实验），

### 6.7.6 M6 验收记录（画布化：节点框 + 连线，2026-10-16）

**做了什么**（§3.2 的选型逐条落地，口径见 [完善计划 §5.5.5](分支对话插件·完善计划.md)）：

| 层 | 结果 |
| --- | --- |
| 布局纯函数 | `src/client/tree-layout.ts` 的 `layoutTree(view)` 不再返回"行"，而是 `{ nodes, edges, size, hiddenTotal, hasOrphans }`：`nodes[i]` 带 `{x,y,width,height}`（固定 `NODE_W=208 × NODE_H=62`），`edges[i]` 带 `{from,to,axis,path,x1,y1,x2,y2}`。算法 = 经典紧凑树（叶子按深度优先序占槽位，内部节点居中于首末子节点）→ 子树占连续槽段、彼此不重叠 |
| 端点几何 | **主轴**：父下缘中点 → 子上缘中点（一条竖线，走两框之间的空隙，**不穿框**）；**分支**：父右缘中点 → 竖直车道 → 子左缘中点，车道按子节点序号错开 `±14px`（≤4 车道）避免多子时**线穿过中间的子框** |
| 主轴/分支 | `axis`：**合成的主轴边恒为 `main`**；其余按"父子是否同一 `sessionId`"判。页面把 `main` 画成实线（B10 的轴线）、`branch` 画成虚线 |
| **布局方向** | **主轴向下、分支向右**：主轴（同会话相邻轮次）同列向下叠；分支（跨会话）向右每层一列。同一父节点的多个分支同列上下叠、且排在父框下方；互不相连的根各自成块自上而下叠放。所以 12 轮主轴画布只占**一列宽**（`2×PADDING + NODE_W`） |
| **主轴合成（显示层）** | 真机上同一会话的轮次在树文档里是**平铺**的兄弟（`children` 全空），所以轴线原本没有数据来源。排布时在**纯函数层**把"同一父节点下 / 一起为根、同一会话、**轮次严格连续**（`n → n+1`）"的节点串成一条主轴，锚点顺延到前一个轮次；合成边带 `synthetic: true`，**不写树文档、不影响导出**。**主轴优先于分支**（主轴下游即使也是真孩子，也走"向下"那条路），而"父就是当前节点的真父子"保持真层级。折叠主轴上某一轮 → **下游整条链一起隐藏**（链上的隐藏数单独统计，否则会"越级上前"） |
| 页面 | `panel.tsx`：`.dsh-branch-canvas`（双向滚动视口）→ `.dsh-branch-surface`（`scale()` 缩放）→ 一层 `.dsh-branch-wires`（`pointer-events:none` 的 SVG）+ 绝对定位的 `.dsh-branch-node` 框。框内：折叠把手、状态点、轮次号、标题（两行 `-webkit-line-clamp` 截断）、「＋」建分支、折叠计数 |
| 缩放 | 工具条 `− / 100% / ＋` 与 `Ctrl+滚轮`，范围 30%~200%；**按容器宽自动缩放到适配**（下限 30%，再小就不让人读字了） |
| 视图状态 | 缩放与滚动位置记在**模块级** `src/client/view-state.ts`（不是 `useState`）：官方 shell 切到别的面板会**卸载**本页，官方布局 store 也是瞬态的，所以只能自己记。语义是"**用户手动调过缩放就不再自动适配**；没调过则跟着内容重算"（早先用"是否已适配过"当门禁，导致第一次之后永不适配，已改）。滚动位置必须**等树排出来**再贴（挂载那一刻 `scrollHeight` 是 0，贴了会被夹成 0） |
| 样式 | `panel.css`：旧的 `.dsh-branch-tree-*`（行/轨道/徽标/小按钮）删除，换成画布/框/连线类名；容器查询下"徽标让位、画布收紧"，**框与线永不退化** |
| 夹具 | `tools/build/panel-preview.mjs` 与页面**同构**地渲染整块画布（同一套类名 + `data-dsh-branch-*`），并参数化出**折叠态夹具**做 F-4 的前后对照 |
| 断言 | `tools/smoke/tree-layout.mjs` 换成坐标/边/端点/不重叠/折叠重排；`tools/smoke/layout-check.mjs` 增加"框有边框""`path` 数 = 边数""框不重叠""端点贴框""框不越出画布""画布内无 `│├└─` 轨道字符" |

**有意丢掉的旧机制**：`MAX_RAILS` 轨道压缩、"每行必须有轨道字符"的断言。
深树不再靠截断轨道，而是靠**画布双向滚动 + 缩放**（F-5 的新口径）。

## 7. 与 DSH 及既有插件的关系

| 对象 | 关系 |
| --- | --- |
| `dsh-session-archive` | 互补：archive 管全库归档/删除/统计；本插件管树与锚点。本插件不提供"删除会话"。 |
| `git-graph` | 无关：它管 git 分支与 worktree；两者都可能出现"分支"字样，文档中必须区分。 |
| `task-board` / `dsh-ssh` | **参照物**：它们已用同一套 `sidebar.panellist` + `main` 配对实现"官方风格的可切换页"，本插件照此办理。 |
| **子智能体（subagents）** | **排除对象**（第 7 条裁决）：模型自己派出的子智能体不进树。`ctx.subagents` 保留为 v2「让模型自己开分支」的扩展位。 |
| DSH 官方侧边栏 | 宿主：本插件在 `sidebar.panellist` 加一行、在 `main` 加一页，用同一个 id 配对；不抢官方 `root` 槽。 |
| 官方"分叉会话"入口 | 注意区分：`WorkspaceBrowserInjected.forkSession()` 是**复制前缀**的官方分叉（在最后一轮处 fork 并打开子会话），与本插件"不继承上下文"的子对话是**两种不同动作**，不要混用。 |
